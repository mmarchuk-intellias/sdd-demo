When a booking ends with no arrival after it was rebooked, its station hold failed, its site was full or faulted, its
reminder was not delivered, or its grace timer fired late, I want to decide the no-show fee myself instead of having
it created automatically, so I can keep fees off drivers whom the platform or the site let down.

## Acceptance criteria

Scenario: S1 · happy path · A failed station hold goes to ops, not to a fee
  Given a booking whose station hold failed
  And no arrival is recorded by the end of its grace period
  When the booking is released
  Then no no-show fee line is created automatically
  And the booking appears in the ops exception queue with the exclusion that applies to it

Scenario: S2 · happy path · Ops waive the fee with a reason code
  Given an excluded booking is in the ops exception queue
  When an ops user waives the fee with a reason code
  Then no no-show fee line exists for the booking
  And the booking's history shows the decision with the ops user, the reason code and the time

Scenario: S3 · happy path · Ops create the fee with a reason code
  Given an excluded booking is in the ops exception queue
  When an ops user creates the fee with a reason code
  Then exactly one no-show fee line is created for the booking, at the site's configured amount
  And the booking's history shows the decision with the ops user, the reason code and the time

Scenario: S4 · failure · An undelivered reminder excludes the fee
  Given the pre-slot reminder of a booking was reported undelivered
  When the booking is released after grace with no arrival
  Then no no-show fee line is created automatically
  And the booking appears in the ops exception queue

Scenario: S5 · failure · A late grace timer excludes the fee
  Given the grace timer of a booking with no arrival fired late
  When the booking is released
  Then no no-show fee line is created automatically
  And the booking appears in the ops exception queue

Scenario: S6 · failure · A decision without a reason code is refused
  Given an excluded booking is in the ops exception queue
  When an ops user tries to create or waive the fee without a reason code
  Then the decision is refused
  And the booking stays in the queue

Scenario: S7 · edge case · A no-show after a fault rebooking
  Given a booking was rebooked after a charger fault
  And the driver does not arrive within the grace period of the new allocation
  When the booking is released
  Then no no-show fee line is created automatically
  And the booking appears in the ops exception queue

Scenario: S8 · edge case · A no-show after the site was full
  Given a booking's site was full at station-hold time and the booking was not rebooked
  And the driver does not arrive within the booking's grace period
  When the booking is released
  Then no no-show fee line is created automatically
  And the booking appears in the ops exception queue with its site-full exclusion shown

## Notes

- A-019: a site-full booking gets no fee. A-028: timers may fire late during maintenance. Q-002: the payer is open; the
  decision here holds in every option.
- S8 was added in the Step 3.1 red-team pass: without it, an implementation that excluded only fault rebookings and
  failed station holds would pass S1 – S7 while charging drivers whose site was full (A-019).
- A failed station hold includes a driver's report that the stall was blocked (REQ-046, FT-02.1). The queue is
  US-124; an arrival with no charging session is JS-111.
- Q-023: who reviews the queue out of hours is undecided (REQ-316 is parked).
