# US-220 · Signed, single-use links in driver messages

As a driver, I want the links in my booking messages to open my bookings without a password but to stop working for
anyone else, so that I reach my booking in one tap between rides and a link that leaks cannot be reused to reach my
bookings.

## Acceptance criteria

Scenario: S1 (happy path) The first open of a link
  Given a driver received a message with a link
  And the driver's phone completed a one-time code for the driver within the set period (REQ-241)
  When the driver opens the link for the first time
  Then the driver page opens without a password
  And it shows only that driver's bookings

Scenario: S2 (happy path) The link keeps working on the same phone
  Given a driver opened a link on a phone that completed a one-time code for the driver within the set period
  When the driver opens the same link again on that phone before the set time after the booking's grace period ends
  Then the driver page opens again without a password

Scenario: S3 (failure) The link is opened on a second phone
  Given a link has already been opened on one phone
  When the same link is opened on another phone
  Then no booking is shown
  And the page tells the reader how to get a new link by texting from the registered number

Scenario: S4 (failure) The link has been altered
  Given a link whose signature does not match its content
  When anyone opens it
  Then no booking and no personal data are shown

Scenario: S5 (failure) The link has expired
  Given the set time after the booking's grace period has passed
  When the driver opens the link on the phone that first opened it
  Then no booking is shown
  And the page tells the driver how to get a new link by texting from the registered number

Scenario: S6 (edge case) The driver asks for a new link
  Given a driver whose link no longer works
  When the driver texts a request for a new link from the registered number
  Then the driver gets a new link that opens the driver's own bookings
  And the same request from any other number gets no link

Scenario: S7 (edge case) A link never reaches another driver's booking
  Given two drivers of the same fleet each have a booking
  When one driver opens a link from their own message
  Then no page reached from that link shows the other driver's booking

## Notes

- Depends on A-006 (signed links, no password) and Q-028. "The set time" is a configured value.
- What the driver texts to get a new link (a keyword such as "link", or any message) is a design detail for Step 3.3,
  with the keyword list (JS-228 Notes).
- A link opened first on a phone that has not completed a one-time code shows only site, time and the booking's
  one-tap actions: REQ-241 v2 (CR-001, JS-221); viewing the booking in full still needs the code, so S1 and S2 keep
  the verified phone. The red team added the verified-phone precondition to S1 and S2 so they do not contradict REQ-241. A link forwarded after the driver opened it does not open on the second phone (S3); the shift-partner case
  in JS-221 works only if the link is forwarded before the driver opens it.
- Baseline: constitution N15 (drivers use signed links), SC3, SC5 (no tokens in logs).
