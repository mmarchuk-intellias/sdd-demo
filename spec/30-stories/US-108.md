As Amperlane ops, I want to extend the grace period of a single booking with a reason code, up to the site's maximum,
so that a driver who is a few minutes away keeps the booking instead of becoming a no-show.

## Acceptance criteria

Scenario: S1 · happy path · An extension within the site's maximum
  Given a booking is in its grace period at a site whose maximum grace extension is configured
  When an ops user extends the booking's grace period within that maximum, with a reason code
  Then the booking is not released before the extended grace period ends
  And the booking's history shows the extension with the ops user, the reason code and the time

Scenario: S2 · failure · An extension beyond the site's maximum is refused
  Given a booking is in its grace period
  When an ops user tries to extend it beyond the site's maximum
  Then the extension is refused
  And the booking keeps its current end of grace

Scenario: S3 · failure · An extension without a reason code is refused
  Given a booking is in its grace period
  When an ops user tries to extend it without a reason code
  Then the extension is refused

Scenario: S4 · failure · A released booking cannot be extended
  Given a booking was already released at the end of its grace period
  When an ops user tries to extend its grace period
  Then the extension is refused
  And the booking stays released

Scenario: S5 · edge case · Arrival inside the extension counts
  Given ops extended a booking's grace period
  When the driver scans the QR code at an EVSE of the site after the original end of grace and before the extended end
  Then arrival is recorded on the booking
  And the booking is not released

Scenario: S6 · edge case · Repeated extensions stay within the maximum
  Given ops already extended a booking's grace period once
  When an ops user extends it again so that the total extension would exceed the site's maximum
  Then the second extension is refused

Scenario: S7 · edge case · Only that booking changes
  Given ops extended the grace period of one booking at a site
  When another booking at the same site reaches the end of its grace period with no arrival
  Then that other booking is released at the end of the site's grace period

## Notes

- A-020: extending grace is an ops override only, up to a maximum set per site with its grace (A-003). CF-021 is
  needs-decision; the other options are parked (REQ-305, REQ-306, REQ-307). Q-004.
- The per-site maximum is a per-site parameter (REQ-146, FT-01.7). Drivers report running late in US-107.
- S6 reads "up to a maximum set per site" as a cap on the total extension of one booking; confirmed in the Step 3.1
  red-team pass, since a per-action cap could be repeated without limit and would void the station's grace term
  (A-003, A-020).
