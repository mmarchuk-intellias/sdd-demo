# JS-405 · No driver names or phone numbers in data that leaves production

When pilot or platform data leaves production, as an export shared outside Amperlane, a data-room extract or a copy
used to seed staging, I want driver names and phone numbers removed from every field, free text included, so I can
share and test with real booking data without exposing a single driver.

## Acceptance criteria

Scenario: S1 (happy path) An export shared outside Amperlane
  Given bookings selected for an export to a party outside Amperlane
  When the export is produced
  Then no field of the output, free-text comments included, contains any driver's name or phone number
  And booking ids, sites, slots and outcomes are kept

Scenario: S2 (failure) A phone number written in an unusual format inside free text
  Given a pilot comment that contains a driver's phone number written with spaces and without a country code
  When the data is prepared to leave production
  Then the phone number does not appear in the output in any format

Scenario: S3 (failure) A driver's name inside free text
  Given a comment that names the driver of the booking
  When the data is prepared to leave production
  Then the name does not appear in the output

Scenario: S4 (failure) The final check still finds a name or phone number
  Given an output in which a scan finds a phone number in any format, or the name of any driver the platform or the
    migrated pilot history holds, including drivers no longer registered
  When the export or copy is about to be released
  Then it is not released
  And the field where the match was found is reported to the person who requested it

Scenario: S5 (edge case) Seeding staging from the migrated pilot history
  Given staging is to be seeded with the migrated pilot history
  When the seed is loaded
  Then staging holds no driver name or phone number from production

Scenario: S6 (edge case) One driver's bookings can still be grouped
  Given an export in which one driver has several bookings
  When the export is produced
  Then each of that driver's bookings carries the same driver id
  And that id is not a name or phone number, nor derived from one, so it cannot be turned back into either from the output

## Notes

- The CTO's practice for the pilot sample: "We'll strip names and phone numbers" (SRC-C1@00:44:59).
- Applies to the data-room report (REQ-095) and to staging seeds (A-034); staging never reaches real drivers
  (REQ-237, US-422). The raw export itself is US-404.
- A driver who is the subject of an export inside Amperlane (for example a fleet's own invoice) is out of scope: the
  requirement covers data shared outside Amperlane or used outside production.
- Red team: a scan limited to registered drivers misses pilot drivers who were never registered and numbers of people
  named in free text (S4); a hash of the phone number used as driver id passes "not a phone number" but is reversed
  by trying every number (S6).
