# US-204 · Upload the LIC session CSV for reconciliation

As Amperlane ops, I want to upload the CSV export from the LIC ChargePoint portal whenever it arrives and have only
the rows not taken in before added, so that LIC sessions can be reconciled against bookings without double counting,
however irregularly the export is made.

## Acceptance criteria

Scenario: S1 (happy path) Ops uploads a new LIC export
  Given a CSV export from the LIC ChargePoint portal that the platform has not seen
  When ops uploads it
  Then every session row in it is stored as LIC session data for reconciliation
  And the result shows ops how many rows were taken in and how many were skipped
  And the upload is recorded in the audit trail with the ops person and the time

Scenario: S2 (failure) The export overlaps one uploaded earlier
  Given an earlier LIC export was uploaded
  And a new export repeats some of its rows and adds new ones
  When ops uploads the new export
  Then only the rows not taken in before are stored
  And the repeated rows are skipped and counted as skipped

Scenario: S3 (failure) The file is not a usable LIC export
  Given a file that lacks a column the LIC import needs, or is not a CSV
  When ops uploads it
  Then no row from the file is stored
  And ops is told which columns are missing or why the file was rejected

Scenario: S4 (failure) The CSV never changes live status
  Given the attendant last reported an LIC EVSE as free
  And an uploaded LIC export shows a session on that EVSE
  When the export is taken in
  Then the live status of the EVSE is unchanged
  And it is still shown as "last updated by attendant at <time>"

Scenario: S5 (edge case) The same file is uploaded twice
  Given an LIC export has been uploaded
  When ops uploads the same file again
  Then no new row is stored
  And the result shows every row as skipped

## Notes

- Depends on Q-011: the CSV fields are unknown (integrations.md U-7), so the columns S3 checks and what identifies a
  row as "already taken in" (a session id, or EVSE plus start time) are set once Q-011 is answered. A-021 keeps LIC on
  the CSV plus the attendant view for the MVP; Q-010 is the longer-term option.
- Who uploads the CSV into the platform (the attendant makes the export, CTX-062) is a design detail for Step 3.3;
  this story assumes Amperlane ops.
- Matching the rows to bookings is REQ-161 and REQ-214 (FT-10.4).
