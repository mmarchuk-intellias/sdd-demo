# JS-417 · Personal data deleted or anonymised when its retention period ends

When a record's retention period, set by counsel for its data type, has passed and no dispute or finance need still
requires it, I want the platform to delete or anonymise it automatically, so I can keep only what disputes and finance
need, as the CTO asked, without anyone having to remember to purge data.

## Acceptance criteria

Scenario: S1 (happy path) A driver's personal data reaches the end of its period
  Given a driver whose personal data has passed the retention period set for driver personal data
  And no open dispute or finance need refers to the driver
  When the retention period ends
  Then the driver's name, phone number and other personal data are deleted or replaced by a pseudonym without any person acting
  And the driver's bookings, audit entries and ledger entries remain, under the pseudonym

Scenario: S2 (failure) An open dispute still needs the data
  Given a driver whose personal data has passed its retention period
  And a dispute on one of the driver's bookings is still open
  When the platform's retention run reaches the driver
  Then the data that dispute needs is kept until the dispute is closed and the dispute window has passed

Scenario: S3 (failure) Ledger entries refer to the driver
  Given a driver whose personal data has passed its retention period
  And ledger entries refer to that driver
  When the platform's retention run reaches the driver
  Then no ledger entry is deleted or changed in amount
  And the ledger entries refer to the driver's pseudonym

Scenario: S4 (edge case) Counsel has not set a period for a data type
  Given a data type for which counsel has not yet set a retention period
  When the platform's retention run happens
  Then nothing of that data type is deleted
  And the data register shows that data type's period as not set

Scenario: S5 (edge case) A driver who becomes active again
  Given a driver who has not booked for a while and whose retention period has not yet ended
  When the driver books again
  Then the driver's personal data is not purged at the date it would otherwise have been

## Notes

- "Keep what we need for disputes, delete the rest" (SRC-C2@00:50:34). Depends on A-025 (retention matrix; counsel
  sets the periods) and Q-022. The dispute window is A-047 (Q-043). The ledger is append-only (constitution N19).
- Location rules (opt-in, arrival events only) stay with FT-03.2 (epics.md, EP-13 grouping logic). One driver's
  request to be anonymised is US-418.
- Red team: a purge job that runs once a year passes S1 while keeping data for up to a year past its period. A-058
  (Q-022) sets it: the purge runs at least daily, so data is gone within one day after its period ends; backups are
  not edited but expire on their own schedule, and a restore re-applies every deletion and anonymisation made since.
