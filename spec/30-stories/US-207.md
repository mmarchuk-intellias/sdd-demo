# US-207 · Every status view shows its age and flags stale status

As Amperlane ops, I want every view of EVSE status to show when that status was observed and to flag it when it is
too old, so that nobody acts on stale status as if it were live.

## Acceptance criteria

Scenario: S1 (happy path) Fresh status at a connected site
  Given an EVSE at a connected site whose status was observed less than 60 seconds ago
  When anyone opens a view that shows the EVSE's status (ops console, station portal, attendant view)
  Then the view shows the status with the time it was observed, in the site's time zone (A-013)
  And the status is not flagged as stale

Scenario: S2 (failure) Status older than 60 seconds at a connected site
  Given an EVSE at a connected site whose status was last observed more than 60 seconds ago
  When anyone opens a view that shows its status
  Then the status is flagged as stale
  And the view shows how old it is

Scenario: S3 (failure) The site's status feed is down
  Given a connected site whose status feed has been unavailable for several minutes
  When ops opens the site in the ops console
  Then each EVSE shows its last known status, flagged as stale, with its age
  And no EVSE is shown as free unless that was its last observed status

Scenario: S4 (edge case) LIC status comes from the attendant
  Given the LIC attendant last set an EVSE's status at a given time
  When anyone opens a view that shows that EVSE's status
  Then the view shows "last updated by attendant at <time>" with that time
  And the 60-second stale flag does not apply to it

Scenario: S5 (edge case) A view stays open while the status ages
  Given a view shows a connected-site EVSE status that is not stale
  When 60 seconds pass with no new status for that EVSE while the view stays open
  Then the view flags the status as stale without being reloaded

Scenario: S6 (edge case) EVSEs with different ages on one view
  Given a site board lists EVSEs whose statuses were observed at different times
  When ops opens the board
  Then each EVSE shows its own observation time and its own stale flag

## Notes

- Baseline: constitution N2 and data-model INV-9. The ops console site board is REQ-190; the attendant view is
  REQ-158.
- LIC status depends on the attendant using the attendant view: A-021, Q-049, Q-010 (integrations.md U-13).
- The driver PWA shows slots, not EVSE status; if a later story shows EVSE status to drivers, this story applies to
  that view too.
