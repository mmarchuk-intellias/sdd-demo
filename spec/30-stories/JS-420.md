# JS-420 · A runbook already used for every alert and external-system outage

When an alert fires, or an external system such as a CSMS, Twilio or Stripe goes down, after hypercare has ended, I
want a written runbook for it that an Amperlane engineer has already used at least once, so I can restore service
with Amperlane's own two engineers instead of calling Intellias.

## Acceptance criteria

Scenario: S1 (happy path) Every alert and external system is covered at the end of hypercare
  Given the alert rules in production and the external systems the platform depends on
  When hypercare ends
  Then each alert rule and each external system has a written runbook
  And no step of any runbook needs Intellias staff to carry it out
  And each runbook has a recorded use by a named Amperlane engineer who followed it end to end, in a drill or a real
    incident, before hypercare ended

Scenario: S2 (failure) An alert rule with no runbook
  Given an alert rule in production that has no runbook
  When the handover is reviewed
  Then the alert rule is listed as an open handover item

Scenario: S3 (failure) A runbook used only by Intellias
  Given a runbook whose only recorded uses are by Intellias staff
  When the handover is reviewed
  Then that runbook is listed as an open handover item

Scenario: S4 (edge case) An alert added during hypercare
  Given a new alert rule added to production during hypercare
  When hypercare ends
  Then it also has a runbook used by an Amperlane engineer before hypercare ended, or it is listed as an open handover item

Scenario: S5 (edge case) An external system with no API
  Given LIC, where session data arrives as a CSV export from the ChargePoint portal rather than through an API
  When the CSV export stops arriving
  Then a runbook covers that outage like any other external-system outage

## Notes

- Amperlane has two engineers (CTX-007); "With two engineers, twelve services is twelve pagers" (SRC-C2@00:54:57).
  Hypercare is March 2027 (glossary). Who is on call is Q-039.

- Red team: a runbook whose last step is "escalate to Intellias", or a "use" that was a read-through, passes the
  original S1; S1 now excludes both.
