# JS-221 · A booking link opened on an unverified phone shows only site, time and one-tap actions

When a link to my booking is opened on a phone that has not confirmed a one-time code for me, such as my shift
partner's phone after I forward the link, I want that phone to see only the booking's site and time and its one-tap
actions, so I can share what the next shift needs and act on the booking in one tap without exposing my details or
letting anyone change the booking in any other way.

## Acceptance criteria

Scenario: S1 (happy path) The limited view
  Given a booking link is opened for the first time on a phone that has not completed a one-time code for the driver
    within the set period
  When the page loads
  Then it shows the booking's site and time and its one-tap actions, such as cancel and running late
  And it shows no other personal data, vehicle or other booking of the driver

Scenario: S2 (happy path) One-tap actions need no code
  Given the limited view of a booking is open
  When the reader uses one of the booking's one-tap actions: cancel, running late, accept an offered slot or
    alternative, report a faulted EVSE or report a blocked stall
  Then the action is applied to the booking with that one tap
  And no one-time code was asked for

Scenario: S3 (failure) Asking for more than the limited view
  Given the limited view of a booking is open
  When the reader asks to see more details or to change the booking in any other way, such as its slot or vehicle
  Then a one-time code is sent to the driver's registered number
  And nothing more is shown and nothing is changed until the code is entered on that phone

Scenario: S4 (failure) A wrong code
  Given a one-time code was sent to the driver's registered number
  When a wrong code is entered on the phone
  Then no further data is shown and no change is made

Scenario: S5 (edge case) A phone that completed a code recently
  Given a phone completed a one-time code for the driver within the set period
  When a booking link for that driver is opened on it
  Then the full driver page opens without asking for a code

Scenario: S6 (edge case) A phone whose code is too old
  Given a phone completed a one-time code for the driver longer ago than the set period
  When a booking link for that driver is opened on it
  Then the page shows only the limited view as in S1

## Notes

- REQ-241 v2 (CR-001): no one-tap action needs the code (cancel, running late, accept an offered slot or alternative,
  report a faulted EVSE or a blocked stall); the Gate 2 decision had exempted cancelling only. Booker and charging
  driver may differ and links travel between shift drivers (CTX-029). Accepted risk (CR-001): the holder of a
  forwarded link can act on that booking in these ways, as it could already cancel it.
- Depends on A-006 and Q-028. "The set period" is a configured value; how many wrong codes are allowed is a design
  detail for Step 3.3.
- Interaction with REQ-240 (US-220): the link is single-use per phone, so a link the driver already opened does not
  open on the partner's phone at all. This story applies when the first phone to open a link is unverified.
- Interaction with REQ-100 (US-212 S7): booking on an unverified phone needs the code first.
