As Amperlane ops, I want a summary of the rebookings the platform made automatically after a fault, and to undo any of
them, so that I can correct a rebooking that does not suit a driver or that followed a false fault.

## Acceptance criteria

Scenario: S1 · happy path · The summary of a fault
  Given the platform handled the bookings of faulted EVSE A automatically
  When an ops user opens the summary for that fault
  Then it lists each affected booking with its outcome: rebooked (from which EVSE to which), offered alternatives, or sent to the ops exception queue

Scenario: S2 · happy path · Undo one rebooking
  Given EVSE A is back in the pool (JS-118)
  And a booking was rebooked automatically from EVSE A to EVSE B
  When an ops user undoes that rebooking with a reason code
  Then the booking is back on EVSE A at its original time
  And the charging driver gets a message naming EVSE A
  And the booking's history shows the undo with the ops user and the reason code

Scenario: S3 · failure · The original capacity is taken
  Given another booking now holds EVSE A for the original time
  When an ops user tries to undo a rebooking from EVSE A
  Then the undo is refused
  And the booking stays rebooked

Scenario: S4 · failure · The original EVSE is still out of the pool
  Given EVSE A is still faulted
  When an ops user tries to undo a rebooking from EVSE A
  Then the undo is refused
  And the booking stays rebooked

Scenario: S5 · failure · An undo without a reason code is refused
  Given a rebooking that could be undone
  When an ops user tries to undo it without a reason code
  Then the undo is refused

Scenario: S6 · edge case · Undoing one rebooking leaves the others
  Given the platform rebooked several bookings of EVSE A automatically
  When an ops user undoes one of them
  Then the other rebookings of that fault are unchanged

## Notes

- A-017 and CF-022: ops get a summary and can undo a rebooking.
- What "undo" restores, and whether an undo is allowed once the driver has arrived at, or is charging on, the EVSE the
  booking was rebooked to, are design details for Step 3.3. S2 and S4 read undo as returning the booking to its
  allocation before the rebooking, only while that EVSE is in the pool; the reviewer should confirm.
