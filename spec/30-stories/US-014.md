# US-014 · Onboard a site in any time zone without a code change

As a member of Amperlane ops, I want to onboard a new site in the ops console, in whatever time zone it is, and make it bookable
only when I mark it live, so that new partner sites on a CSMS we already integrate start taking bookings without
waiting for a release and a new metro needs no change to the booking core.

## Acceptance criteria

Scenario: S1 (happy path) Ops onboards a site and marks it live
  Given ops enters a new site in the ops console with its station operator, address, time zone, supply pattern, EVSEs, connectors, capacity rules and terms
  And the site's CSMS is one the platform already integrates, or the site has no API (supply pattern C)
  When ops marks the site live
  Then the site appears in the open-slot view and can be booked
  And no code change or deployment was needed

Scenario: S2 (failure) A site not marked live cannot be booked
  Given a site has been entered in the ops console but not marked live
  When a booker looks for it or sends a booking request for it
  Then it is not shown in the open-slot view
  And the booking request is refused

Scenario: S3 (failure) Only ops can onboard a site or mark it live
  Given a station operator or a fleet manager is signed in
  When that user tries to create a site or mark one live
  Then the action is refused

Scenario: S4 (edge) A site outside Eastern time runs end to end
  Given a test site is onboarded in the America/Los_Angeles time zone on the same platform release that runs the NYC sites
  When it is booked, allocated and released end to end
  Then its slots, booking, allocation and release are shown in Pacific time with the zone indicated
  And no change to the booking core was made for it
