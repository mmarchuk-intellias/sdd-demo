As Amperlane ops, I want to force-confirm a held or unconfirmed booking and to force-release a booking, each with a
reason code, so that I can settle a booking for a driver on the phone without breaking the site's capacity rules.

## Acceptance criteria

Scenario: S1 · happy path · Force-confirm within capacity
  Given a held booking whose slot still has capacity under the site's capacity rules
  When an ops user force-confirms it with a reason code
  Then the booking is confirmed
  And its history shows the override with the ops user, the reason code and the time
  And the booker and the charging driver get the booking confirmation

Scenario: S2 · happy path · Force-release has the effect of a cancellation
  Given a confirmed booking with a station hold
  When an ops user force-releases it with a reason code
  Then its capacity returns to the slot calendar
  And the station hold is cleared: the charger reservation is cancelled, or site staff are told to clear the stall
  And the charging driver gets the same message as for a cancellation
  And the booking's history shows the override with the ops user, the reason code and the time

Scenario: S3 · failure · A force-confirm that would break capacity is refused
  Given a held booking whose slot has no capacity left under the site's capacity rules, or whose overlapping bookings could then no longer all be allocated to distinct compatible EVSEs with the site's buffer (REQ-147)
  When an ops user tries to force-confirm it
  Then the force-confirm is refused
  And the booking stays as it was

Scenario: S4 · failure · An override without a reason code is refused
  Given a held or a confirmed booking
  When an ops user tries to force-confirm or force-release it without a reason code
  Then the override is refused

Scenario: S5 · edge case · A retried force-release acts once
  Given an ops user's force-release is sent twice with the same idempotency key
  When both requests arrive
  Then the booking is released once
  And the driver gets one message

## Notes

- Overrides were accepted by the CEO (CTX-035). "Same rules" are REQ-004, REQ-007 and REQ-101; the cancellation effect
  follows REQ-150, REQ-153 and REQ-035; S5 follows REQ-236; the audit follows REQ-053 and constitution N17.
- S3 names the pool check (REQ-147, A-014) because a held booking has no EVSE yet (REQ-003): "its allocation would

  protects later allocation (Step 3.1 red-team pass).
- REQ-057 equates a force-release with a cancellation for capacity, station hold and driver messages only; whether a
  force-release can carry a no-show fee is a design detail for Step 3.3.
