# US-208 · Live status only from a partner site's own sources

As Amperlane ops, I want live EVSE status to come only from a partner site's CSMS or its attendant, and every other
charging site to appear only as static data, so that no booking decision rests on availability the platform cannot
actually see.

## Acceptance criteria

Scenario: S1 (happy path) Live status comes from each partner site's own source
  Given Gowanus and JFK are connected through their CSMS APIs and LIC reports through the attendant view
  When ops opens the live status of the three sites
  Then the status of Gowanus and JFK EVSEs comes from their CSMS APIs
  And the status of LIC EVSEs comes from the attendant view
  And each status shows its source

Scenario: S2 (failure) A public directory lists a partner site
  Given NLR AFDC or Open Charge Map holds a record for a partner site
  When the platform reads that directory data
  Then the live status of the site's EVSEs does not change
  And the directory data is never shown as live availability

Scenario: S3 (failure) The LIC CSV is not a status source
  Given an LIC export from the ChargePoint portal is taken in
  When the export shows EVSE activity
  Then the live status of LIC EVSEs does not change
  And it still shows "last updated by attendant at <time>"

Scenario: S4 (failure) A driver's report is not a status
  Given a driver reports from the booking page that an EVSE is not working
  When the report is received
  Then the EVSE's live status does not change because of the report alone
  And ops gets an alert linked to the site and the EVSE (REQ-191)

Scenario: S5 (edge case) A charging site that is not a partner site
  Given a charging site that is not a partner site appears in a platform view
  When anyone looks at it
  Then it is shown only as static data with no live availability
  And it shows no status age

## Notes

- OCPI 2.2.1 Locations are an allowed source too, but only where a station operator peers over OCPI; the OCPI gateway
  (REQ-166) is I and no NYC launch site uses it (A-015), so no scenario here assumes it.
- Showing non-partner sites on the driver map is REQ-030 (I). S5 applies only if such a view exists.
- S4 relies on REQ-191 (Y, FT-04.1) for the ops alert.
- S1 and S3: LIC live status depends on the attendant using the attendant view: A-021, Q-049, Q-010
  (integrations.md U-13).
