# US-005 · Cancel a booking in one tap or by SMS keyword

As a driver, I want to cancel a booking with one tap from any message about it, or by replying with a cancel keyword,
so that when a ride comes in I can give the slot back while driving instead of becoming a no-show.

## Acceptance criteria

Scenario: S1 (happy path) One tap on the page opened from a message
  Given a driver has a confirmed booking
  And the driver opens the page from a message about that booking
  When the driver taps cancel
  Then the booking is cancelled with no confirmation dialog and no sign-in step
  And its capacity is offered in the open-slot view as soon as the cancellation is confirmed

Scenario: S2 (happy path) One tap on the driver page
  Given a driver opens the driver page, which lists a confirmed booking
  When the driver taps cancel on that booking
  Then the booking is cancelled with no confirmation dialog and no sign-in step

Scenario: S3 (happy path) Cancel keyword with the booking code an SMS gives
  Given a driver has more than one confirmed booking and received an SMS about one of them, which gives that booking's
    code
  When the driver replies to that SMS with a cancel keyword and that booking code
  Then only the booking that SMS was about is cancelled
  And the driver gets a reply naming the booking cancelled

Scenario: S4 (failure) The booking is no longer active
  Given a booking was already cancelled or released
  When the driver taps cancel on a page opened from an earlier message about it
  Then the booking stays as it was
  And the page shows that the booking is no longer active

Scenario: S5 (failure) A cancel reply with the code of an inactive booking cancels nothing else
  Given a driver has one confirmed booking and an earlier SMS about another booking that is already cancelled, which
    gives that booking's code
  When the driver replies to the earlier SMS with a cancel keyword and the booking code that SMS gives
  Then the confirmed booking stays confirmed
  And no reply names the confirmed booking as cancelled

Scenario: S6 (edge) Cancelling shortly before the slot returns capacity at once
  Given a confirmed booking was already allocated to an EVSE shortly before its slot
  When the driver cancels it
  Then its capacity is offered in the open-slot view as soon as the cancellation is confirmed
  And another booker can place a hold for the same slot straight away

## Notes

- Whether a late cancellation still counts as a no-show for the fee is Q-042 (REQ-171, EP-03), covered by A-049 (a
  cancellation after the cut-off goes to ops as a fee decision); this story makes no fee promise.
- Clearing the station hold of a cancelled booking is US-027 (REQ-035, REQ-153). No one-tap action, cancelling
  included, needs a one-time code (REQ-241 v2, CR-001). Only the booker's or the charging driver's number may send SMS commands (REQ-242, EP-06). Keywords
  in English, Spanish and Bengali are REQ-220 (EP-06).
- SMS has no reply threading. Every message about a booking gives its booking code and asks for it in a keyword reply
  (SS-302, SS-310).
- Gate 3 (2026-10-28, decision G3-1 option (a), Mykola Marchuk): S3 and S5 amended so that the reply carries the
  booking code the SMS gives (v2). Without the code no rule can tell which message a bare keyword answers. A bare cancel
  keyword cancels the driver's only active booking and the reply names the booking cancelled (Step 3.1 bucket-5 #5,
  SS-310 clauses 4 and 7); with several active bookings it cancels none and the reply lists their codes (SS-310 clause
  5). Residual risk accepted: a bare keyword meant for an older message cancels the only active booking, and the reply
  shows which. approved_with is kept until re-approval at Gate 3.
