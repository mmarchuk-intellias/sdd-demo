As Amperlane ops, I want each fault-affected booking the platform could not place in my exception queue, with the
alternatives its driver was offered and the driver's answer, and proposed rebookings I can approve in bulk, so that I
can settle a charger fault in a few actions instead of rebooking each booking by hand.

## Acceptance criteria

Scenario: S1 · happy path · Unplaced bookings reach the queue in time
  Given EVSE A faults and some of its bookings cannot be placed at the site
  When the set time after the fault passes
  Then each of those bookings is in the ops exception queue
  And each shows the alternatives offered to its driver and the driver's answer so far

Scenario: S2 · happy path · Proposals approved in bulk
  Given the platform proposed a rebooking for each unplaced booking of the fault
  When an ops user approves the selected proposals in one action
  Then each approved booking is rebooked as proposed, with the reason code 'moved — charger fault' and the ops user as actor
  And each charging driver gets a message about the new booking in the driver's language
  And the approved bookings leave the queue

Scenario: S3 · failure · A proposal is no longer valid
  Given the slot of one proposal was taken after it was proposed
  When an ops user approves it together with other proposals in one action
  Then that booking is not rebooked and stays in the queue, marked as not placed
  And the other approved proposals are applied

Scenario: S4 · failure · The driver chose first
  Given the driver of an unplaced booking accepted one of the offered alternatives
  When an ops user opens the queue
  Then the booking is no longer in the queue
  And its proposal can no longer be approved

Scenario: S5 · failure · Ops reject a proposal
  Given a proposal for an unplaced booking
  When an ops user rejects it
  Then the booking stays in the queue without a proposal, for ops to handle on its own

Scenario: S6 · edge case · No proposal is possible
  Given no free compatible capacity exists at the site or at nearby sites for an unplaced booking
  When the booking reaches the queue
  Then it shows that no proposal exists
  And ops can rebook or release it from the ops console (US-128, US-129)

## Notes

- A-017 and CF-022: same-site rebooking is automatic, and ops bulk-approve proposals only for the bookings the platform
  could not place. Q-038 is covered by A-050: the proposals may place a booking on any free compatible EVSE at the
  site, including one that would otherwise serve walk-ups, but never on one a walk-up is using.
- Q-023: who works the queue out of hours is an undecided client decision; out-of-hours escalation is REQ-316 (parked V).
  The queue holds in every option.
- The driver's side is JS-120; the summary and undo of automatic rebookings is US-122.
