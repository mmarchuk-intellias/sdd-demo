# US-201 · Gowanus EVSE status through AMPECO

As Amperlane ops, I want Gowanus EVSE status read through Kinship's AMPECO API, so that the platform and I know
whether each Gowanus EVSE is free, in use or faulted without anyone phoning Kinship.

## Acceptance criteria

Scenario: S1 (happy path) A status change at Gowanus reaches the platform through AMPECO
  Given Gowanus is connected to the platform through the AMPECO API
  When an EVSE at Gowanus changes status in AMPECO
  Then the platform holds for that EVSE the status AMPECO reported
  And the status carries the time it was observed and AMPECO as its source

Scenario: S2 (failure) The AMPECO API is unreachable
  Given the AMPECO API does not answer
  When the status of a Gowanus EVSE has not been received or fetched for more than 60 seconds (constitution N2)
  Then the status of that EVSE is shown as stale with its age
  And no Gowanus booking is cancelled, released or rebooked because of the outage
  And once the AMPECO API answers again, the next status AMPECO reports for each EVSE replaces the stale one

Scenario: S3 (failure) AMPECO sends a status twice or out of order
  Given AMPECO delivers the same status event twice, or an older status after a newer one
  When the platform processes both events
  Then the EVSE's status changes at most once for the repeated event
  And the status held is the one with the latest observation time

Scenario: S4 (failure) AMPECO sends a status the platform cannot map
  Given AMPECO sends a status event that fails validation, or names a charger or EVSE id not mapped to a Gowanus EVSE
  When the platform receives it
  Then no Gowanus EVSE's status changes because of it
  And each Gowanus EVSE keeps its last valid status with that status's own observation time

Scenario: S5 (edge case) An EVSE that is not reservable
  Given a Gowanus EVSE that is not flagged as reservable
  When its status changes in AMPECO
  Then the platform holds the new status for that EVSE exactly as for a reservable EVSE
