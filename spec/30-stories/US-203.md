# US-203 · JFK EVSE status through ChargeLab

As Amperlane ops, I want JFK's EVSE status read from Jamaica Bay Energy's ChargeLab API, so that the platform and I
know whether a JFK EVSE is free before the driver arrives, at a site where status is the only live signal and no
charger reservation exists.

## Acceptance criteria

Scenario: S1 (happy path) ChargeLab pushes a status change
  Given JFK is connected to the platform through the ChargeLab API
  And ChargeLab sends status changes by webhook
  When an EVSE at JFK changes status
  Then the platform holds the new status for that EVSE
  And the status carries the time it was observed and ChargeLab as its source

Scenario: S2 (happy path) The platform polls ChargeLab
  Given JFK is connected to the platform through the ChargeLab API
  When the platform polls ChargeLab for JFK's EVSE status
  Then each JFK EVSE holds the status ChargeLab returned
  And each status carries the time it was fetched and ChargeLab as its source

Scenario: S3 (failure) The ChargeLab API is unreachable
  Given the ChargeLab API does not answer
  When JFK's status age passes 60 seconds (constitution N2)
  Then every JFK EVSE status is shown as stale with its age
  And no JFK booking is cancelled, released or rebooked because of the outage

Scenario: S4 (failure) ChargeLab returns data that fails validation
  Given ChargeLab returns a status response that does not match its expected schema
  When the platform receives it
  Then the response is rejected and no EVSE status changes because of it
  And each JFK EVSE keeps its last valid status with that status's own observation time

Scenario: S5 (edge case) No charger reservation at JFK
  Given a JFK booking is allocated to an EVSE
  When the site's station-hold offset before the slot is reached
  Then no charger reservation is sent to ChargeLab
  And site staff get a station-hold request for that EVSE (REQ-026)

## Notes

- Depends on Q-012: the ChargeLab API docs, whether status is pushed or polled, and whether 60-second freshness is

  Q-012 is answered. Whether Amperlane holds ChargeLab API credentials is not stated (integrations.md I-2): an external
  dependency. A-022 sets the baseline.
- Freshness and the poll that reconciles lost webhooks are JS-206; the outage behaviour beyond S3 is JS-210.
