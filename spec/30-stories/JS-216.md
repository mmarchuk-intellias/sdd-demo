# JS-216 · One text acts once, even if it arrives twice

When I send Amperlane one text to book, cancel or say I am running late, I want it acted on exactly once even if it
reaches Amperlane more than once, so I can trust the one reply I get and never end up with two bookings or two
confirmations from one message.

## Acceptance criteria

Scenario: S1 (happy path) A booking text is delivered twice
  Given a driver's text "GOW 1645" with a provider message id was processed into a booking
  When the messaging provider delivers the same message id again
  Then no second booking or hold is created
  And the driver gets no second reply or confirmation

Scenario: S2 (failure) A cancel text is delivered twice
  Given a driver's cancel text with a provider message id cancelled a booking
  When the messaging provider delivers the same message id again
  Then the booking stays cancelled and nothing else changes
  And the driver gets one cancellation reply only

Scenario: S3 (failure) A WhatsApp message is delivered twice
  Given a driver's WhatsApp message with a provider message id was processed
  When the messaging provider delivers the same message id again
  Then it is not processed again and the driver gets no second reply

Scenario: S4 (edge case) The first delivery failed before it was processed
  Given a driver's booking text reached the platform but was not processed because of a platform error
  When the messaging provider delivers the same message id again
  Then the message is processed once
  And exactly one booking or offer results, with one reply

Scenario: S5 (edge case) The driver really sends the same text twice
  Given a driver sent "GOW 1645" and got a reply
  When the driver sends "GOW 1645" again as a new message with a new provider message id
  Then the platform treats it as a new request and replies to it

Scenario: S6 (edge case) A repeat arrives days later
  Given a message id was processed less than 7 days ago (A-035)
  When the messaging provider delivers the same message id again
  Then it is not processed again

## Notes

- "Processed" means the message's effect (booking, cancellation, reply) has been applied; S4 checks that a failed first
  attempt does not block the retry.
- Fixes the pilot defect of two confirmations twice a week (CTX-044). The confirmation rule itself is REQ-089
  (US-223); idempotency of commands and webhooks in general is REQ-103, REQ-106 and REQ-236 (FT-14.3).
- Baseline: constitution N8; data-model INV-4. WhatsApp: Q-034.
- S5: what a second, genuine "GOW 1645" books is decided by the booking rules (EP-01), not by this story.
