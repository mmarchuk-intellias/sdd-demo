# US-403 · One documented rule when the Sheets and Airtable disagree

As the Amperlane engineer who knows the pilot data (Priya Nair), I want the migration to settle every disagreement
between a site's pilot Google Sheet and Airtable by one documented precedence rule and to list each conflict it
settled, so that I can check the decisions against what ops actually did on shift instead of trusting whichever source
happened to load last.

## Acceptance criteria

Scenario: S1 (happy path) A conflict is settled by the rule and listed
  Given a pilot booking whose slot differs between the site's pilot Google Sheet and Airtable
  When the migration runs
  Then the booking is loaded with the value the documented precedence rule picks
  And the conflict list shows the booking, both source values, the value kept and the rule applied

Scenario: S2 (failure) A booking is in only one of the two sources
  Given a slot marked taken in the site's pilot Google Sheet with no matching booking in Airtable
  When the migration runs
  Then the case is settled by the same documented precedence rule
  And it appears in the conflict list with the source that holds it

Scenario: S3 (failure) The rule does not cover the disagreement
  Given a disagreement on a field for which the documented precedence rule names no winning source
  When the migration runs
  Then no value is chosen silently
  And the booking is on the rejected list with the reason "conflict not covered by the precedence rule"

Scenario: S4 (edge case) The rule changes between runs
  Given a completed run and a changed documented precedence rule
  When the migration is run again
  Then every conflict is settled again under the changed rule
  And the conflict list shows the changed rule for each entry

Scenario: S5 (edge case) The sources agree
  Given a pilot booking whose Sheet cell and Airtable row agree
  When the migration runs
  Then the booking is not in the conflict list

Scenario: S6 (edge case) The order in which the sources load makes no difference
  Given pilot bookings on which the site's pilot Google Sheet and Airtable disagree
  When the migration is run once loading Airtable first and once loading the Sheets first
  Then both runs keep the same value for every booking
  And both produce the same conflict list

## Notes

- In practice the source of truth was the Sheet the ops person on shift had open (CTX-042, SRC-C2@00:02:34), and a
  nightly script copied only some of it to Airtable. The rule itself is a design detail for Step 3.3, to be validated
  by Priya Nair with the raw export (Q-020, A-026).
- Re-classifying outcomes is US-402; reconciling counts is US-401.
- Red team: "last loaded wins" could be written down and called the documented rule; S6 makes the result independent
  of load order, which is what the "so that" asks for.
