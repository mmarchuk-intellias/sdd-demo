When I learn that an EVSE has failed before the platform does, from a driver's report or from the station operator, I
want to rebook all its bookings in one action, so I can protect the rest of the day's drivers before the shift-change
burst instead of rebooking them one at a time.

## Acceptance criteria

Scenario: S1 · happy path · One action rebooks all bookings of the EVSE
  Given EVSE A has bookings later that day
  And the platform has received no fault status for EVSE A
  When an ops user rebooks all bookings of EVSE A in one action, with a reason code
  Then each booking goes through the same fault rebooking as on a CSMS fault: rebooked to a compatible EVSE at the site with the reason code 'moved — charger fault', or offered alternatives and placed in the ops exception queue
  And EVSE A gets no new allocations until it returns to service (JS-118)
  And each rebooking's history shows the ops user as actor

Scenario: S2 · failure · Automatic rebooking already started
  Given the platform already started fault rebooking for EVSE A
  When an ops user rebooks all bookings of EVSE A in one action
  Then no booking is rebooked twice

Scenario: S3 · failure · The action without a reason code is refused
  Given EVSE A has bookings later that day
  When an ops user tries to rebook all of them without a reason code
  Then the action is refused
  And no booking changes

Scenario: S4 · edge case · Bookings left on the EVSE by an interrupted rebooking
  Given automatic rebooking of EVSE A stopped partway and left some bookings on EVSE A with ops exceptions
  When an ops user rebooks all bookings of EVSE A in one action
  Then exactly those bookings are rebooked or offered alternatives
  And their exceptions close

## Notes

- A-017 and CF-022: automatic rebooking is the main path; this one-action manual path is the fallback. Drivers and the
  station operator are today's fault detectors (CTX-048); a driver's report is JS-117.
- REQ-054 implies that ops can take an EVSE out of the pool; no requirement states it except for maintenance holds
  (REQ-184). How the single action takes the faulted EVSE out is a design detail for Step 3.3. A station operator marking an EVSE out of service is REQ-193 (I).
