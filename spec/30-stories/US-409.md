# US-409 · Real drivers on the platform before the Amperlane Concierge is switched off

As the Amperlane CEO, I want the platform to run real bookings with real drivers at Gowanus, JFK and LIC for a set
period before 2027-03-01, and the Amperlane Concierge switched off only once the written go-live criteria are met, so
that launch day is not the first time a real driver depends on the platform and the pilot is switched off on
evidence rather than on the calendar.

## Acceptance criteria

Scenario: S1 (happy path) Real bookings at all three sites during the set period
  Given the set period before 2027-03-01 has started
  When registered drivers of the pilot fleets, not Amperlane or Intellias staff, book at Gowanus, JFK and LIC through
    the platform
  Then those bookings run end to end in the platform with real drivers at each of the three sites
  And the go-live record shows, per site, the real bookings run and the evidence against each written criterion

Scenario: S2 (failure) A criterion is not met at the planned switch-off
  Given a planned switch-off of the Amperlane Concierge before 2027-03-01
  And one written go-live criterion is not met
  When that planned switch-off arrives
  Then the Amperlane Concierge is not switched off
  And the go-live record lists each criterion still open

Scenario: S3 (failure) One site has not been proven
  Given LIC has had no real booking run end to end in the platform during the set period
  When the go-live criteria are reviewed before 2027-03-01
  Then LIC is shown as not proven
  And the Amperlane Concierge is not switched off

Scenario: S4 (edge case) The criteria are met early
  Given every written go-live criterion is met before 2027-03-01
  When the switch-off is approved
  Then the Amperlane Concierge is switched off
  And the go-live record shows who approved it, when, and the evidence for each criterion

- Invoicing of bookings run in the platform during the set period is a design detail for Step 3.3 (US-408).
