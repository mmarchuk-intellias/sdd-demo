# JS-024 · Station holds at Gowanus during an AMPECO outage

When the Gowanus CSMS API is unreachable or its status is stale as a station hold falls due, I want to have the station
hold run through site staff as at a status-only site, so I can keep Gowanus bookings held through a vendor outage.

## Acceptance criteria

Scenario: S1 (happy path) API unreachable at station-hold time
  Given the AMPECO API is unreachable
  When the station hold for a Gowanus booking falls due
  Then no charger reservation is sent
  And site staff get a station-hold request for the allocated EVSE's stall, as at a status-only site

Scenario: S2 (failure) Status is stale
  Given the AMPECO API answers but the status held for Gowanus EVSEs is older than 60 seconds (constitution N2)
  When the station hold for a Gowanus booking falls due
  Then station holds at Gowanus run as at a status-only site, through site staff

Scenario: S3 (failure) The site staff request cannot be delivered either
  Given the AMPECO API is unreachable
  And the station-hold request to Gowanus site staff cannot be delivered
  When the set time passes
  Then an ops exception for the booking appears in the ops queue

Scenario: S4 (edge) The API recovers
  Given Gowanus station holds were running through site staff during an outage
  When the AMPECO API is reachable again and its status is fresh
  Then the next station holds for EVSEs flagged as reservable are sent as charger reservations again

## Notes

- "Stale" is constitution N2 (status of a connected site older than 60 s; age measured per A-031).
- Depends on: A-012, and A-048 with Q-059 (how Gowanus site staff receive and acknowledge station-hold requests;
  Q-041 and A-046 cover JFK). S3 applies the delivery rule of REQ-026 (US-025).
- While status is stale, bookings are still accepted and an ops exception is raised (REQ-168, EP-05).
