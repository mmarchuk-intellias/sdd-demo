# SS-338 · Breach scope listing: individuals and data elements, vendor-held included

As the Audit & data protection component, I need to list the individuals and data elements a suspected breach may have
exposed, including the data only vendors hold, and to keep the breach procedure's readiness on record, so that
Amperlane notifies the right people about the right data under the NY SHIELD Act.

## Acceptance criteria (EARS)
1. [Event] When a user with the breach-scope role asks for the scope of a suspected breach through one account over a
   time window, the Audit & data protection component shall list each driver whose personal data that account viewed or
   exported in the window (SS-335), with the data elements exposed.
2. [Event] When a user with the breach-scope role asks for the scope of an exposed copy of a data store as it was at a
   stated time, the Audit & data protection component shall list every individual whose personal data that store held
   at that time, with the data elements stored for them.
3. [Ubiquitous] The Audit & data protection component shall record in the data register, for each personal-data field,
   the vendors it is sent to, and list those vendors with each data element of a breach scope.
4. [Ubiquitous] The Audit & data protection component shall mark each credential, licence number and account number in
   a breach scope as covered by the NY SHIELD Act (SS-342).
5. [Unwanted] If part of the stated scope is a period or a copy for which the platform holds no records, then the Audit
   & data protection component shall name that part as unresolved and mark the list as incomplete.
6. [Ubiquitous] The Audit & data protection component shall list drivers anonymised before the breach window by
   pseudonym only, as already anonymised.
7. [Unwanted] If a user without the breach-scope role asks for a breach scope, then the Audit & data protection
   component shall refuse it and record a security event (SS-334).
8. [Unwanted] If no breach-notification procedure with counsel's review against the NY SHIELD Act and a named
   notification owner is recorded, then the Audit & data protection component shall report the procedure as missing
   to the go-live record (SS-423 clause 7), as evidence against the go-live criterion for the breach procedure.
