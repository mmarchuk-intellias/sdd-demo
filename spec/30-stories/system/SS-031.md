# SS-031 · Signed printable QR code per EVSE, stable on reprint

As the Inventory & site configuration module, I need to produce one signed, printable QR code for each EVSE that
always identifies the same EVSE, so that site staff can post a code at every EVSE and a scan proves which EVSE the
driver is at.

## Acceptance criteria (EARS)
1. [Event] When an ops user asks for a site's QR codes, the Inventory & site configuration module shall produce one
   printable code for each EVSE the site has at that moment, each showing its site and EVSE in readable text and
   encoding a link that identifies the site and the EVSE and carries the platform's signature.
2. [Ubiquitous] The Inventory & site configuration module shall produce the same code content for an EVSE every time
   it is printed.
3. [Event] When the content of a scanned code is presented for verification, the Inventory & site configuration module
   shall return the site and the EVSE it identifies if its signature is valid, for arrival from that scan (SS-124
   clause 2).
4. [Unwanted] If the content of a scanned code was not produced by the platform or was altered after it was produced,
   then the Inventory & site configuration module shall identify no EVSE and answer INVALID_QR_CODE, so no arrival is
   recorded from it (SS-124 clause 10).
5. [Unwanted] If a user who is not ops asks for a site's QR codes, then the Inventory & site configuration module shall
   refuse the request.

## Notes
- Covers US-102 S1 – S5. Recording arrival from a valid scan within the arrival window is SS-124 (US-101); a scan
  from a phone with no link to the booking is bucket-5 #16 (SS-124).
- A-012: site staff or the attendant put the codes up. Whether a station operator may print its own sites' codes is
  not stated (US-102 note). Rotating the signing key would change every code and require a reprint; the key is managed
  under constitution N14.
