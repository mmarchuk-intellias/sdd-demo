# SS-029 · Reservable flag per EVSE changed by ops without a release

As the Inventory & site configuration module, I need each EVSE to carry its own reservable flag that ops change in the
console and that takes effect at once, so that EVSEs get charger reservations as soon as their firmware is fixed and
stop the moment a charger starts rejecting them.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Inventory & site configuration module shall hold a reservable flag for each EVSE, independent of
   the flags of the other EVSEs at its site.
2. [Event] When ops set or clear an EVSE's reservable flag in the ops console, the Inventory & site configuration module
   shall change that EVSE's flag only, in force from that instant with no software release, and emit one
   configuration-changed event with the EVSE, the values before and after, ops as actor and the time.
3. [Ubiquitous] The Inventory & site configuration module shall answer a query for an EVSE's reservable flag with the
   value in force at the moment of the query, so the station-hold step uses the flag in force when a booking's
   station-hold offset is reached, also for bookings allocated before a change.
4. [Unwanted] If a user who is not ops tries to change an EVSE's reservable flag, then the Inventory & site
   configuration module shall refuse it and leave the flag as it was.
5. [Event] When an EVSE is created without a reservable flag, the Inventory & site configuration module shall record it
   as not reservable.

## Notes
- Covers US-022 S3, S4 and the flag behind S1 and S2. Which station hold a booking gets (charger reservation or
  site-staff request) at its station-hold offset is SS-116 and SS-118, which do not list US-022 (ss-log-1).
- Depends on Q-009 (which chargers accept reservations), Q-013 and A-004 (per charger or per EVSE). Clause 5 keeps a
  new EVSE on the site-staff path until ops confirm it accepts reservations (CTX-060: 10 of 16 chargers).
- Audit with before and after values: SS-333 (REQ-262 per-EVSE settings).
