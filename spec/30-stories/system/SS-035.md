# SS-035 · Self-hosted workflow engine in Amperlane's AWS account

As the Booking workflows module, I need the workflow engine to run self-hosted in Amperlane's own AWS account, so that
year one needs no extra vendor contract and the booking timers and their history stay in Amperlane's infrastructure.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Booking workflows module shall run on a self-hosted Temporal deployment in Amperlane's AWS
   production account, defined in Amperlane's Terraform, with no hosted workflow service in the path of any booking
   timer.
2. [Ubiquitous] The Booking workflows module shall keep workflow history, timers and the engine's persistence store
   only in Amperlane's AWS accounts.
3. [Unwanted] If no service outside Amperlane's AWS accounts can be reached, then the Booking workflows module shall
   keep firing booking timers and recording workflow history.
