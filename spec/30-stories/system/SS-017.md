# SS-017 · Maintenance hold on EVSEs or capacity for a time window

As the Booking engine, I need to take named EVSEs, or a number of units of capacity, at a site out of booking for a
time window when ops place a maintenance hold, so that planned work never sends a driver to an EVSE that is out of
service.

## Acceptance criteria (EARS)
1. [Event] When an ops user places a maintenance hold on named EVSEs of a site for a time window with a reason code,
   the Booking engine shall record it with its EVSEs, window, ops user, reason code and time, and leave those EVSEs out
   of the pool check, the open-slot view, offers and the EVSEs it returns for allocation, for every slot that overlaps
   the window.
2. [Event] When a maintenance hold on named EVSEs is recorded, the Booking engine shall emit one maintenance-hold event
   with the site, the EVSEs and the window, so that the bookings affected are rebooked and re-checked as on a fault
   (SS-036, SS-113).
3. [Event] When an ops user places a maintenance hold on a number of units of capacity at a site for a time window with
   a reason code, the Booking engine shall count those units in every slot of the window against the cap and in the
   pool check as bookings that can use any EVSE.
4. [Unwanted] If a maintenance hold's window ends before it starts, it has no reason code, or it names neither an EVSE
   nor a number of units, then the Booking engine shall refuse it with the code INVALID_MANUAL_HOLD and record nothing.
5. [Ubiquitous] The Booking engine shall apply a maintenance hold only to slots that overlap its window, so its EVSEs
   or units return to the pool for slots after the window with no ops action.

## Notes
- Covers US-130 S1, S5, S6, S7, and the trigger of S2 – S4 (the rebooking itself is SS-113 under the saga SS-036; the
  station operator's notice is SS-313). The audit entry for the hold (US-412 S7) is SS-332.
- A-018 and Q-035: a maintenance hold takes EVSEs out physically, so affected bookings are rebooked as on a fault with
  'moved — maintenance' (REQ-185). Return-to-service rules after a fault (REQ-194) do not apply to it.
- A repeated hold request with the same key is SS-014.
