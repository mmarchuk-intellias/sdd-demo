# SS-312 · Messages the platform cannot act on, and unregistered numbers: to ops, acknowledged

As the Messaging component, I need to hand every inbound message the platform cannot act on to ops with its full text
and the sender's language, and to acknowledge it, so that a driver who writes something unexpected still gets an
answer from a person without phoning.

## Acceptance criteria (EARS)
1. [Event] When an inbound message from a registered number is not understood (SS-310, SS-311), the Messaging component
   shall raise a "message not understood" ops exception (SS-219) with the full text, the time, the driver, the driver's
   active bookings and the driver's stored language, or "no language set".
2. [Event] When the Messaging component raises that exception, the Messaging component shall send the driver one
   acknowledgement in the driver's stored language, English if none is stored, that promises no response time.
3. [Ubiquitous] The Messaging component shall show ops, and use for the acknowledgement, the driver's stored language,
   not the language the message is written in.
4. [Unwanted] If the same provider message id arrives again, then the Messaging component shall raise no second
   exception and send no second acknowledgement.
5. [Event] When an inbound message arrives from a number registered to no fleet, the Messaging component shall create
   no hold or booking, offer no sign-up or account, and raise the exception of clause 1 with the text and
   "unregistered number".
6. [Optional] Where replies to unregistered numbers are enabled (Q-056), the Messaging component shall send such a
   number one reply in English, Spanish and Bengali saying that the number is not registered and to ask the fleet.
7. [Unwanted] If no agreement to booking messages is in force on the channel of a registered driver's unclear message
   (SS-304), then the Messaging component shall send no acknowledgement and show on the exception that the driver was
   not acknowledged.
