# SS-427 · Architecture gates: modular monolith, TypeScript on PostgreSQL and AWS, mature open source

As the Platform & operations component, I need the pipeline to keep the platform one modular monolith in TypeScript on
PostgreSQL and AWS, with module boundaries and open-source maturity checked on every change, so that Amperlane's two
engineers can run and change it after handover.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Platform & operations component shall build the back end as one deployable from one codebase,
   whichever processes it runs as (API or workflow workers).
2. [Unwanted] If a change adds a separately deployed back-end service without an ADR approved by the Amperlane CTO,
   then the Platform & operations component shall fail the pipeline run.
3. [Unwanted] If a module imports another module's internals, or its SQL reads or writes another module's schema, then
   the Platform & operations component shall fail the pipeline run.
4. [Unwanted] If a change adds application source code in a language other than TypeScript, or a system of record
   other than PostgreSQL, then the Platform & operations component shall fail the pipeline run.
5. [Ubiquitous] The Platform & operations component shall host every environment on AWS.
6. [Unwanted] If a change adds an open-source dependency that fails the maturity check of constitution code convention
   3, then the Platform & operations component shall fail the pipeline run unless an ADR approved by the Amperlane CTO
   names that dependency.
