# SS-335 · Personal-data access log: every view and export of a driver's personal data

As the Audit & data protection component, I need every view and export of a driver's personal data by an ops, finance,
fleet, station-operator or site-staff user recorded, so that Amperlane can tell a driver, counsel or an auditor exactly
who saw what and when.

## Acceptance criteria (EARS)
1. [Event] When a response to an ops, finance, fleet, station-operator or site-staff user contains a driver's personal
   data, in a page, list, search result, export or API response, the Audit & data protection component shall append
   one access entry per driver in it with the user, the user's organisation, the driver's internal id, the data
   elements, the booking where there is one, whether it was a view or an export, and the time.
2. [Ubiquitous] The Audit & data protection component shall record reads at the API, so a portal page and a direct API
   call that return the same data are recorded the same way.
3. [Event] When location evidence is viewed in an open dispute, the Audit & data protection component shall record the
   user, the driver, the booking and the time.
4. [Unwanted] If the access entry cannot be written, then the Audit & data protection component shall withhold the
   response.
5. [Ubiquitous] The Audit & data protection component shall allow no update or deletion of an access entry by any user.
6. [Ubiquitous] The Audit & data protection component shall keep access entries by the driver's internal id, so they
   remain and show the pseudonym after the driver is anonymised.

## Notes
- REQ-263 v2 (CR-006) names ops, finance, fleet, station-operator and site-staff users (JS-415 S8). Which driver data
  site staff and station operators see is A-053 (Q-048).
- Ops may see location evidence only within an open dispute (REQ-259, SS-135). These entries are what SS-338 uses to
  scope a breach through a compromised account (JS-416 S1).
