# SS-046 · Completed: an arrived booking closes on a matched session record or an ops outcome

As the Booking engine, I need to record an arrived booking as Completed once a session record is matched to it or ops
accept it in reconciliation, so that the default completed definition, the Completed state (SS-229), counts the
bookings that turned into a charge.

## Acceptance criteria (EARS)
1. [Event] When the Ledger & invoicing component emits a session-matched event for a booking in the Arrived state
   (SS-407 clause 3), the Booking engine shall record the booking as Completed with the reason code
   COMPLETED_SESSION_MATCHED and the system as actor.
2. [Event] When an ops user closes the reconciliation case of a booking in the Arrived state with the outcome "a manual
   match" or "accepted without a session record" (SS-408 clauses 6 and 12), the Booking engine shall record the booking
   as Completed with the reason code COMPLETED_SESSION_MATCHED or COMPLETED_WITHOUT_SESSION_RECORD respectively, and
   that ops user as actor.
3. [Unwanted] If a session-matched event or a case outcome names a booking that is not in the Arrived state, such as a
   no-show, a cancelled booking or a booking already Completed, then the Booking engine shall leave its state unchanged
   and record no state change.
4. [Unwanted] If a command would change the state of a Completed booking (cancel, release, rebook, grace extension),
   then the Booking engine shall refuse it and leave the booking Completed.
5. [State] While a booking is Arrived and has neither a matched session record nor a reconciliation outcome of clause
   2, the Booking engine shall keep it in the Arrived state, also after its slot window has ended.

## Notes
- CR-013 (2026-10-29), gap G-1 of data-model.md v1: SS-229 clause 2 counts the Completed state by default, but no clause
  entered it, so the north-star count would have stayed at zero. The entry rule is data-model.md v0 §3 ("the session
  ended, and either a session record is matched or ops/the attendant confirmed it"), without the attendant: no clause
  of the attendant view confirms a charge (U-13), so the confirmation is ops' reconciliation outcome, which SS-408's
  notes already call "the fallback of data-model.md's Completed state".
- At sites with no session records (all three until Q-009, Q-011 and Q-012 are answered; U-6, U-7), an arrived booking
  reaches Completed only through ops' outcome; SS-408 clause 12 accepts one site and period at once.
- Q-017 stays open: ops can change the completed definition over the stored evidence (SS-229). This system story only
  gives the default definition a state to count.
- A no-show booking whose session record arrives later (SS-408 clause 2) stays NoShow whatever the outcome (clause 3);
  whether a definition counts it is the definition's question (US-326 S6).
- Covers US-326 S2 ("counted by the default definition, the Completed state"). The reason codes join SS-020's
  catalogue.
