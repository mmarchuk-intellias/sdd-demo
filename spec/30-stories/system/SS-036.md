# SS-036 · Fault-rebooking saga ends every affected booking in a defined state

As the Booking workflows module, I need to run the rebooking of an EVSE's bookings as one durable saga that resumes
after an interruption and ends each affected booking in a defined state, so that a fault at the shift change never
leaves a driver's booking between two EVSEs.

## Acceptance criteria (EARS)
1. [Event] When a fault event for an EVSE (SS-208), an ops one-action rebooking of an EVSE (SS-112) or a maintenance
   hold on an EVSE (SS-017) arrives, the Booking workflows module shall start one saga for that EVSE and that trigger,
   list the bookings it affects and request the rebooking decision of Allocation & rebooking for each (SS-108,
   SS-113): for a fault or a one-action rebooking, the bookings allocated to the EVSE and the site's later bookings
   that day; for a maintenance hold, the bookings allocated to the EVSE inside the hold's window and the site's
   unallocated bookings inside that window.
2. [Ubiquitous] The Booking workflows module shall end each booking a saga affects in exactly one of these states:
   rebooked, kept because it still fits, handed to unplaced handling with its ops exception and, where one can be
   made, its proposal to ops (SS-109, SS-110), or left on its original EVSE with an ops exception.
3. [Unwanted] If a saga stops partway, because of a restart or a step that fails, then the Booking workflows module
   shall resume it after the last booking it completed, and leave on its original EVSE every booking whose step cannot
   complete, raising a 'fault rebooking incomplete' ops exception for it (SS-219).
4. [Unwanted] If a saga for an EVSE is already running when another trigger for the same EVSE arrives, then the Booking
   workflows module shall hand only the bookings that saga has not reached to it, so no booking is rebooked twice.
5. [Event] When ops run the one-action rebooking for an EVSE whose earlier saga left bookings on it with ops
   exceptions, the Booking workflows module shall handle exactly those bookings and report each of their exceptions
   resolved (SS-219 clause 7) once its booking is rebooked or handed to unplaced handling.
