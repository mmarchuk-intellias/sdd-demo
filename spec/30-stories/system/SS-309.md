# SS-309 · Inbound deduplication by provider message id

As the Messaging component, I need to act on each inbound SMS or WhatsApp message exactly once, keyed by the
provider's message id, so that a message the provider delivers twice never makes two bookings, two cancellations or
two replies.

## Acceptance criteria (EARS)
1. [Event] When an inbound SMS or WhatsApp message arrives, the Messaging component shall process it only if its
   provider message id has not already been processed.
2. [Unwanted] If the provider message id was processed within the key retention period (at least 7 days, A-035), then
   the Messaging component shall not process it again, change nothing and send no reply.
3. [Ubiquitous] The Messaging component shall treat a message id as processed only once the message's effect (booking,
   hold, cancellation, report or reply) has been committed, and from then on always.
4. [Unwanted] If processing of a message failed before its effect was committed, then the Messaging component shall
   process a redelivery of the same message id once.
5. [Unwanted] If two deliveries of the same message id arrive at the same time, then the Messaging component shall
   process only one of them.
6. [Event] When a message with a new provider message id arrives, the Messaging component shall process it as a new
   request, even if its text repeats an earlier message.
