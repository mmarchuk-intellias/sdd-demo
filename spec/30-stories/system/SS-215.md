# SS-215 · LIC CSV ingestion: ops upload, validation, each row once, reconciliation only

As the LIC CSV integration (CSMS integrations), I need to take in the LIC ChargePoint portal export whenever ops upload
it, validate it, deliver each session row only once and never touch live status, so that LIC sessions can be
reconciled against bookings without double counting, however irregularly the export is made.

## Acceptance criteria (EARS)
1. [Event] When an Amperlane ops user uploads a valid LIC ChargePoint export, the LIC CSV integration shall deliver each
   session row not taken in before to settlement as an LIC session record for reconciliation, and return to the ops
   user the number of rows taken in and the number skipped.
2. [Unwanted] If the uploaded file is not a CSV or lacks a column the LIC import needs, then the LIC CSV integration
   shall take in no row from it and tell the ops user which columns are missing or why the file was rejected.
3. [Unwanted] If a row was already taken in from an earlier upload, identified by its row key, then the LIC CSV
   integration shall skip it and count it as skipped.
4. [Unwanted] If a row of an otherwise valid file fails validation, then the LIC CSV integration shall skip that row,
   take in the other rows, and list the rejected row with its row number and reason in the result.
5. [Unwanted] If a user who is not Amperlane ops tries to upload an LIC export, then the LIC CSV integration shall
   refuse the upload.
6. [Event] When an upload is processed, the LIC CSV integration shall record it in the audit trail with the ops user,
   the time, the file name and the counts of rows taken in, skipped and rejected.
7. [Ubiquitous] The LIC CSV integration shall pass nothing from the export to the EVSE status service, so the export
   never changes live status.
