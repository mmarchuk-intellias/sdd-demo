# SS-334 · Security event audit: sign-ins, failed sign-ins, role changes, data access, configuration changes

As the Audit & data protection component, I need every sign-in, failed sign-in, role change, production data access
and configuration change recorded with its actor and time from the first release, so that Amperlane can answer a
security team or a SOC 2 auditor from the record.

## Acceptance criteria (EARS)
1. [Event] When a staff, portal or site-staff user signs in or fails to sign in, the Audit & data protection component
   shall append a security event with the account, the outcome, the source and the time, and no password, code or
   token.
2. [Event] When a one-time code is entered for a driver, the Audit & data protection component shall record a driver
   sign-in if the code is accepted and a failed sign-in if it is refused, with the driver, the device and the time, and
   not the code.
3. [Event] When a signed driver link is opened for the first time on a device, the Audit & data protection component
   shall record a driver sign-in with the driver, the device and the time.
4. [Event] When a page is loaded again from a link already opened on the same device, the Audit & data protection
   component shall record no further sign-in for it.
5. [Event] When a role or permission is granted, changed or removed, the Audit & data protection component shall record
   the actor, the user concerned, the role before and after, and the time.
6. [Event] When the production access log (SS-433) reports access to production data outside the platform's
   application, for example from a database console, the Audit & data protection component shall record the person,
   the data store, the access and the time.
7. [Event] When a configuration change is saved, the Audit & data protection component shall record a security event
   with the actor and the time.
8. [Event] When a request is refused as out of scope (SS-323), a text command is refused (SS-322) or a webhook
   signature does not verify (SS-317, SS-218, SS-413 clause 2), the Audit & data protection component shall record a
   security event with what was refused and the time.
9. [Unwanted] If any user, the person who caused a security event included, tries to update or delete it, then the Audit
   & data protection component shall refuse the change and leave the event as recorded.
10. [Ubiquitous] The Audit & data protection component shall record security events in every production release, the
    first one included.
