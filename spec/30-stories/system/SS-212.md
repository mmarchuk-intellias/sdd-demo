# SS-212 · AMPECO charger reservations: send, cancel with retry, typed results

As the AMPECO integration (CSMS integrations), I need to send and cancel Gowanus charger reservations through the AMPECO
API exactly as the station-hold dispatcher asks and return a typed result for each, so that every outcome is recorded
against the booking and no AMPECO answer by itself changes a booking.

## Acceptance criteria (EARS)
1. [Event] When the station-hold dispatcher requests a charger reservation for a Gowanus EVSE with an expiry, the
   AMPECO integration shall send a reservation request for that EVSE with exactly that expiry through the AMPECO API.
2. [Event] When AMPECO answers a reservation request, the AMPECO integration shall return to the dispatcher a typed
   result, accepted with AMPECO's reservation id or rejected with AMPECO's reason, with the time of the answer.
3. [Unwanted] If AMPECO does not answer a reservation request within the site's configured reservation answer timeout,
   then the AMPECO integration shall return the result "not answered" with the time.
4. [Unwanted] If AMPECO answers a reservation request after the AMPECO integration returned "not answered", then the
   AMPECO integration shall pass the late answer to the dispatcher as a late result with its time.
5. [Unwanted] If the dispatcher repeats a reservation request for the same station-hold attempt, then the AMPECO
   integration shall return the first result and send no second reservation.
6. [Unwanted] If the dispatcher requests a charger reservation for an EVSE not flagged as reservable, then the AMPECO
   integration shall send nothing to AMPECO and return the result "not reservable".
7. [Event] When the dispatcher requests cancellation of an accepted charger reservation, the AMPECO integration shall
   send the cancellation through the AMPECO API and, once AMPECO confirms it, return "cancelled" with the time of
   AMPECO's confirmation.
8. [Unwanted] If AMPECO has not confirmed a cancellation, then the AMPECO integration shall resend it at the configured
   cancellation retry interval until AMPECO confirms it or the reservation's expiry has passed.
9. [Ubiquitous] The AMPECO integration shall change no booking; it returns reservation results to the station-hold
   dispatcher only.
10. [Unwanted] If AMPECO does not answer a cancellation request within the site's configured reservation answer timeout,
    then the AMPECO integration shall return "not answered" with the time to the dispatcher.
11. [Event] When the resending of a cancellation under clause 8 ends, the AMPECO integration shall return to the
    dispatcher "cancelled" with the time if AMPECO confirmed it, or "cancellation unconfirmed" if the reservation's
    expiry passed first.

## Notes
- Covers US-232 S1 – S6 (S6 also decided by SS-116), the CSMS side of US-021 S1 and S5 and US-027 S2 and S3. When a
  reservation is sent, its expiry (no earlier than the end of grace) and which booking changes cancel it are SS-116 and
  SS-120 (REQ-024, REQ-153); the fallback after a rejected or unanswered reservation is SS-117 (REQ-155, REQ-023).
- Bucket-5 #11 is SS-120's: this SS retries the vendor call (clause 8); SS-120 raises the ops exception on
  "cancellation unconfirmed". #9 (late acceptance kept) is SS-117's; clause 4 delivers the late answer to it.
- Each result is recorded against the booking by SS-121 (station-hold record). Clause 9 is REQ-023: the booking stays
  confirmed after a rejection and cancelled after an unanswered cancellation.
- Parameters: the site's configured reservation answer timeout (REQ-155, per site in the ss-plan §5.1 list, owned by
  SS-026); the configured cancellation retry interval (#11). Defaults in design.md §8 (A-059).
- R7: charger reservations work on 10 of 16 Gowanus chargers (integrations.md U-1, CTX-060); sandbox access, the
  firmware fix and the list of chargers are Q-009. A-022 sets the March baseline. Retries run as idempotent workflow
  activities (constitution N10, code convention 8).
- P3.4 (2026-10-28): old clause 7 (cancelled or not answered) split into clauses 7 and 10; old clause 8 (resend, then
  return the final result) split into clauses 8 and 11. Clause numbers 1 – 9 are unchanged.
