# SS-015 · Ops booking on behalf of a registered driver under the same rules

As the Booking engine, I need to let an ops user book for a registered driver with exactly the rules of the driver's
own booking, so that a driver who phones in, or a small fleet without portal users, still gets a slot and nothing about
it lives outside the platform.

## Acceptance criteria (EARS)
1. [Event] When an ops user requests a hold and then confirms it for a driver registered to a fleet, a vehicle of that
   fleet and a slot, the Booking engine shall apply the grid, duration, cap, compatibility, pool, party and hold-expiry
   rules of SS-002 to SS-006 and, on confirmation, record the ops user as booker and the driver as charging driver.
2. [Unwanted] If any of those rules refuses the request (slot full, no compatible EVSE, number not registered to the
   vehicle's fleet, hold expired), then the Booking engine shall refuse the ops request with the same reason code a
   driver would get, and for a full slot return the same-site offer of SS-009 to the ops user.
3. [Event] When an ops booking is confirmed, the Booking engine shall return the confirmed booking to the ops console
   in its response and emit the booking-confirmed event with the ops user as booker, so that the charging driver gets
   the confirmation and no message goes to the ops user.
4. [Event] When an ops user books with the reason code 'outage', after a platform outage, a booking honoured or
   arranged by phone during it, the Booking engine shall apply the rules of clause 1 to it also when its slot has
   already started or ended.

## Notes
- Covers US-127 S1 – S5 and US-406 S3 (the booking exists in the platform with ops as booker). US-127 S6 is SS-014.
  That pilot tools stay unchanged (US-406 S3) is SS-222.
- REQ-009 v2 (CR-002) records the ops user as booker. The confirmation in the driver's language is Messaging (SS-300,
  REQ-088); SS-300 does not list US-127 as a parent (ss-log-1).
- A small fleet's drivers are registered by ops (A-023, REQ-206, SS-040). Booking during an outage and recorded later
  uses the 'outage' reason code (SS-020).
- Clause 4 is A-060 (Gate 3, 2026-10-28): after an outage ops record in the platform each booking they honoured or
  arranged by phone from the outage copy (SS-436), a booking whose slot started or ended during the outage included;
  from then on it is a booking like any other (invoiced once by the platform, REQ-232). The arrival or no-show ops
  observed is recorded with the existing actions. The time it was arranged and the time it was recorded are both kept
  (SS-020 clause 6). JS-419 (Y) is the story behind A-060; Q-023 (ops load).
