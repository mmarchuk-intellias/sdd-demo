# SS-306 · Welcome and cut-over messages for newly registered and carried-over drivers

As the Messaging component, I need to welcome each newly registered driver once, and to tell each driver whose pilot
bookings were carried over how to manage them, so that drivers can book, cancel and report running late from their
first shift without being walked through it by ops.

## Acceptance criteria (EARS)
1. [Event] When a number is registered to its first fleet while an agreement to booking messages is recorded for it, the
   Messaging component shall send it one welcome in the driver's language, English if none is stored, explaining how to
   book, cancel and report running late.
2. [Unwanted] If no agreement is recorded for a newly registered number, then the Messaging component shall send no
   welcome and keep the welcome pending.
3. [Event] When an agreement is recorded for a registered number whose welcome is pending (SS-304), the Messaging
   component shall send the welcome then.
4. [Event] When a number that was already welcomed is registered to another fleet, the Messaging component shall send
   it one short welcome naming that fleet.
5. [Unwanted] If a number is registered again to a fleet it is already registered to, for example by re-importing a
   file, then the Messaging component shall send no welcome.
6. [Event] When the cut-over carry-over (SS-421) reports a driver's carried-over bookings, the Messaging component
   shall send that driver one cut-over message in the driver's language, English if none is stored, naming each
   carried-over booking by its code, site and start time with its link, saying how to cancel it and report running
   late, and including the welcome content.
7. [Unwanted] If a welcome and a cut-over message are both due for a number at cut-over, then the Messaging component
   shall send only the cut-over message.
8. [Unwanted] If no agreement is recorded for a driver with carried-over bookings, then the Messaging component shall
   send that driver no cut-over message and report each of those bookings to SS-421 as "driver not told".
9. [Unwanted] If the carry-over runs again, then the Messaging component shall send a cut-over message only for
   carried-over bookings not yet named in one sent to that driver.

## Notes
- Settles bucket-5 item #31: a number registered to a second fleet gets a short welcome naming that fleet; a pilot
  driver whose bookings are carried over gets the cut-over message with the welcome content and no separate welcome.
- Registration by the fleet or by ops: A-023 (SS-037, SS-040, SS-041). Carry-over and its result list for ops: SS-421;
  the cut-over instant: #46, SS-422; the platform takes over the pilot SMS number: A-057.
- Agreement: SS-304. Whether a pilot driver's past use of the pilot number counts as agreement is Q-056; if it does
  not, clause 8 applies to every carried-over driver and ops reach them another way (JS-407 S3).
- STOP after the welcome (US-225 S5): SS-304.
