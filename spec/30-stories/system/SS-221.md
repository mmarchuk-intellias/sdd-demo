# SS-221 · Driver search by mobile number, plate or booking code

As the ops console, I need to find a driver's bookings, messages and fees with one search by mobile number, plate or
booking code, so that ops can answer a driver's call or text without switching tools.

## Acceptance criteria (EARS)
1. [Ubiquitous] The ops console shall search mobile numbers, plates and booking codes with one query and return every
   match, each labelled with the kind of key it matched.
2. [Event] When an ops user searches for a mobile number, written with or without the country code, spaces, dashes or
   brackets, the ops console shall match it as an E.164 number and return the bookings, messages and fees of the
   driver registered with it, in every fleet the number is registered to.
3. [Event] When an ops user searches for a booking code, the ops console shall return that booking with its charging
   driver, booker, vehicle, messages and fees.
4. [Event] When an ops user searches for a plate, the ops console shall return every booking of that vehicle, each with
   its own charging driver, messages and fees.
5. [Unwanted] If no driver, vehicle or booking matches a search, then the ops console shall state that nothing matches.

## Notes
- Covers US-126 S1, S2, S4 and S6. Sending a templated or free-text message from the result (S3, S5, S7) is SS-314.
- Every view of a driver's personal data by ops is recorded in the audit trail (REQ-263 v2, SS-335).
- Drivers registered to several fleets: A-016. Phone numbers are stored in E.164 (constitution code convention 12).
  The full message history with delivery status is REQ-196 (I) and is not assumed: "messages" are the messages the
  platform holds for the booking or driver.
