# SS-435 · Simulated site and sandbox-only staging

As the Platform & operations component, I need a simulated site whose chargers and CSMS API engineers can make fault,
overrun and report late drivers on demand, and a staging environment connected only to sandboxes and simulators, so
that a day like the Gowanus fault can be rehearsed without touching a real charger, a real payment or a real driver.

## Acceptance criteria (EARS)
1. [Event] When an engineer makes an EVSE of the simulated site fault, the Platform & operations component shall
   deliver the fault to staging as a status change through the CSMS integration that a real site of the same supply
   pattern uses, and never by a write into the platform's data.
2. [Event] When an engineer makes the previous session overrun into a booking's slot, or reports a simulated driver as
   late, the Platform & operations component shall produce the CSMS events and driver actions that a real site would
   produce.
3. [Ubiquitous] The Platform & operations component shall offer the Gowanus fault replay ("1:50 PM, charger fault, nine
   bookings") on the simulated site as a scenario that runs repeatedly with the same inputs.
4. [Unwanted] If a staging integration is configured with a production endpoint or live credentials (the AMPECO
   production API, live Stripe keys, a messaging sender that reaches real phone numbers), then the Platform &
   operations component shall not start that integration, so that no request reaches the production system.
5. [Unwanted] If a simulator command names an EVSE of a real site, then the Platform & operations component shall
   refuse the command and send nothing to that EVSE.
6. [State] While no AMPECO sandbox is available, the Platform & operations component shall run staging's AMPECO
   integration against the simulated site standing in for the AMPECO API.
7. [Ubiquitous] The Platform & operations component shall let staging send messages only to numbers in the configured
   staging test number range (SS-339 clause 7), so that no booking message reaches a real driver's phone, also when
   staging is seeded with pilot history.
