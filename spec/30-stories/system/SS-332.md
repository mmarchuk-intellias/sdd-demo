# SS-332 · Append-only audit trail: state changes, overrides, manual ops actions, station holds

As the Audit & data protection component, I need to record every booking state change, override, manual ops action
and station-hold step with its actor, reason code and time in a trail nobody can edit or delete, so that ops can
answer any question about a booking from evidence.

## Acceptance criteria (EARS)
1. [Event] When a component reports a booking state change, an override, a manual ops action, a station-hold attempt or
   answer, or, where the business model has them (Q-001), a payout, the Audit & data protection component shall append
   one entry with the actor (the system or a named person), the action, the target, the reason code, the time and the
   request's correlation id.
2. [Unwanted] If an event to be recorded has no actor or no reason code, then the Audit & data protection component
   shall refuse it, so the change that produced it is not committed.
3. [Ubiquitous] The Audit & data protection component shall allow no update or deletion of an entry by any role, the
   database role the platform itself uses included.
4. [Event] When a correction is recorded, the Audit & data protection component shall append it as a new entry that
   refers to the entry it corrects.
5. [Unwanted] If anyone tries to update or delete an entry, then the Audit & data protection component shall refuse it
   and record the attempt as a security event (SS-334).
6. [Event] When an ops user opens a booking's history, the Audit & data protection component shall return every entry
   for that booking in time order, its station-hold attempts and answers and any manual hold that changed it included.
7. [Ubiquitous] The Audit & data protection component shall refer to people in entries by internal id, never by name or
   phone number, so anonymising a driver leaves every entry intact (SS-337).
