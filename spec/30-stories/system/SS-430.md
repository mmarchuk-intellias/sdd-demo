# SS-430 · Sizing for 10,000 completed bookings a month, proven by a seeded load test

As the Platform & operations component, I need the platform sized for at least 10,000 completed bookings a month in NYC
and proven on staging by a seeded load test before launch and before every release that changes booking, inventory or
workflows, so that the ramp to the Series A milestone does not need a rebuild.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Platform & operations component shall run each load test on a staging environment sized as
   production is, so that a passed load test shows that production supports at least 10,000 completed bookings a month
   over the pilot sites and the new NYC sites.
2. [Ubiquitous] The Platform & operations component shall seed the load-test environment with the migrated pilot
   history and twelve months of bookings at 10,000 completed bookings a month (A-034), counting every seeded booking as
   completed.
3. [Event] When a release is prepared that is the launch release or changes booking, inventory or workflows, the
   Platform & operations component shall run the load test of A-034 on staging and attach its report to the release.
4. [Unwanted] If the load test fails a pass criterion of A-034 (booking API p95, overlapping allocations, duplicate
   bookings, server errors, or a losing attempt without an alternative or a "full" answer), then the Platform &
   operations component shall block the release and name the failed criterion in the report.
