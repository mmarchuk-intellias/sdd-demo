# SS-026 · Per-site booking parameters, versioned and changed without deployment

As the Inventory & site configuration module, I need to hold every configured booking time as a per-site or
platform-wide parameter that ops change without a deployment, versioned so that each booking keeps the values it was
confirmed under, so that each site runs on its partner agreement's terms as soon as they are signed and no booking's
rules shift under it.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Inventory & site configuration module shall hold for every site a value of each per-site booking
   parameter: time grid, booking durations, buffer, hold time, allocation offset, station-hold offset, pre-arrival
   check offset, reminder lead time, grace period, maximum grace extension, arrival-window start, reservation answer
   timeout, site-staff delivery timeout, clear-instruction time, cancellation cut-off and silence time.
2. [Ubiquitous] The Inventory & site configuration module shall hold one platform-wide value, which ops change without
   a deployment, for each other configured time, limit and default that the requirements and system stories name:
   site-full exception time, unplaced-booking exception time, fault reaction time, late-arrival re-offer time, fault
   offer time, station-operator notice time, session-start wait, stable-available time, timer lateness tolerance,
   session match time, session-record read interval, invoice close offset, delivery-status wait, link validity after
   grace, link validity for a driver-page link requested by text, one-time-code validity, verified-device period,
   wrong-code limit, code lockout time, cancellation retry interval for charger reservations, payment retry interval,
   payment check interval, outage-copy refresh interval, outage-copy horizon, number of cross-site alternatives,
   dispute window and default adapter policy for new fleets.
3. [Event] When a site is created, the Inventory & site configuration module shall give each per-site parameter the
   catalogue default, a grace period of 10 minutes included (REQ-034), until ops set a site value.
4. [Event] When ops change a per-site parameter in the ops console, the Inventory & site configuration module shall
   store the site's parameters as a new version in force from that instant, with no deployment.
5. [Event] When a component asks for the parameters of a booking, the Inventory & site configuration module shall
   return the version that was in force at the instant the booking was confirmed.
6. [Unwanted] If a user who is not ops tries to change a per-site or platform-wide parameter, then the Inventory & site
   configuration module shall refuse the change and keep the parameters in force unchanged.
7. [Unwanted] If a change would give a time grid or hold time that is not positive, a booking duration that is not a
   positive multiple of the time grid, a negative buffer or maximum grace extension, a grace period that is not
   positive, a station-hold offset larger than the allocation offset, a pre-arrival check offset not smaller than the
   station-hold offset, or a fault offer time not smaller than the unplaced-booking exception time, then the Inventory
   & site configuration module shall refuse it and keep the version in force.
8. [Event] When a parameter changes, the Inventory & site configuration module shall emit one parameter-changed event
   with the site (or platform), the parameter, the values before and after, the actor and the time.
9. [Ubiquitous] The Inventory & site configuration module shall hold, for each CSMS integration, one value of the
   status poll interval (SS-201), which ops change without a deployment.
