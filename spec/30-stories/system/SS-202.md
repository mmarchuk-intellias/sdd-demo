# SS-202 · Status read model: observed-at, source and stale flag on every status read

As the EVSE status service, I need every status read I serve to carry when the status was observed, where it came from
and whether it is stale, so that no view (ops console, station portal, attendant view, dispute evidence) can present
stale or attendant-reported status as live.

## Acceptance criteria (EARS)
1. [Ubiquitous] The EVSE status service shall return with every EVSE status read the status, its observed-at time with
   the site's time zone, and its source.
2. [Ubiquitous] The EVSE status service shall flag the status of an EVSE at a connected site as stale exactly when that
   EVSE's status age exceeds 60 seconds.
3. [Optional] Where a site's live status source is the attendant view, the EVSE status service shall return each EVSE's
   status as last updated by the attendant at the time of the attendant's update, with no stale flag under the 60-second
   rule.
4. [Unwanted] If an EVSE's status source stops reporting, then the EVSE status service shall keep returning the EVSE's
   last observed status with that status's own observed-at time, never a default or inferred status such as free.
5. [Event] When an EVSE's status age crosses 60 seconds with no new status, the EVSE status service shall publish the
   stale flag to open status subscriptions without waiting for a new status.
6. [Ubiquitous] The EVSE status service shall return with every EVSE status read whether the EVSE is excluded from new
   allocations and, if so, why (fault or silence).
7. [Ubiquitous] The EVSE status service shall return the status age with every status it flags as stale.
