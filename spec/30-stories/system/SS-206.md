# SS-206 · Live status sources: CSMS API, OCPI Locations or attendant only; other sites static

As the EVSE status service, I need to take live EVSE status only from each partner site's own status source and apply
the same status rules whatever that source is, so that no booking decision rests on availability the platform cannot
see and the three supply patterns differ only in where status comes from.

## Acceptance criteria (EARS)
1. [Ubiquitous] The EVSE status service shall accept live status for a site's EVSEs only from the one status source
   configured for the site: its CSMS integration, an OCPI Locations peer, or the attendant view.
2. [Unwanted] If status-like data for a partner site's EVSE arrives from any other input (NLR AFDC or Open Charge Map
   records, the LIC ChargePoint CSV, a driver's fault report), then the EVSE status service shall leave the EVSE's live
   status unchanged.
3. [Unwanted] If a status read asks for a charging site that is not a partner site, then the EVSE status service shall
   return no live status and no status age for it.
4. [Ubiquitous] The EVSE status service shall apply the same rules to EVSEs of every supply pattern (status ordering,
   staleness, fault intake, silence and return to service), so that only the source of a status differs by pattern.

## Notes
- Covers US-208 S1 – S5 (S4 with SS-210), US-204 S4 (with SS-215), US-205 S6 and the status part of US-205 S4. The
  booking, allocation, grace and station-hold parts of US-205 are covered by batch 1 and 2 SS (SS-002, SS-100,
  SS-108, SS-116, SS-127).
- OCPI Locations is an allowed source only where a station operator peers over OCPI; the gateway (REQ-166) is I and no
  launch site uses it (A-015). The discovery layer for non-partner sites (REQ-030) is I.
- LIC live status comes from the attendant view: A-021, Q-049, Q-010, A-054 (integrations.md U-13).
