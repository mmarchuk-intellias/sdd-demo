# SS-217 · Vendor-neutral CSMS interface: no vendor SDK or vendor types in the booking core

As the CSMS integrations, I need to offer the core one vendor-neutral CSMS interface and keep every vendor SDK and type at
the edge, so that moving a site to another CSMS changes only its integration and never the booking core.

## Acceptance criteria (EARS)
1. [Ubiquitous] The CSMS integrations shall expose to the core modules only the vendor-neutral CSMS interface:
   normalised status events, poll requests and results, charger-reservation requests and typed results, session-start
   events, session records, and each integration's declared capabilities.
2. [Ubiquitous] The CSMS integrations shall keep every CSMS vendor SDK, vendor package and vendor type inside their own
   integration module, so that no core module imports one.
3. [Ubiquitous] The CSMS integrations shall declare, for each integration, which capabilities it supports (status
   webhook, status poll, charger reservation, session-start events, session records), so that the core selects
   behaviour by capability, never by vendor.
4. [Unwanted] If a core module requests a capability that the site's CSMS integration does not declare, then the CSMS
   interface shall return "not supported" without calling any vendor.
5. [Event] When a site's CSMS integration is switched to another integration by configuration, the CSMS integrations
   shall serve the site through the same interface, so that the booking core's test suite passes with no change to core
   code.

## Notes
- Enabler: REQ-105 has no story (ss-plan §4.2). Basis: ADR-003, constitution code convention 5 (import lint in CI
  fails on a vendor package outside `integrations/`).
- Clause 5 is tested with the simulator integration (SS-435) beside AMPECO and ChargeLab: switching the simulated site
  between integrations leaves the core suite unchanged.
- Clause 3 lets SS-116 and SS-118 choose a charger reservation or a site-staff request by capability (SS-214 clause 6)
  and gives each unconfirmed capability (integrations.md U-6, U-8, U-14) a defined fallback (constitution R7).
- P3.4 (2026-10-28): "port" is a glossary Avoid word (it means an EVSE); the software boundary is now called the CSMS
  interface, as SS-415 does for payments.
