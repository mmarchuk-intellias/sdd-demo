# SS-122 · Gowanus degraded mode: station holds through site staff while AMPECO is down or stale

As the Station-hold dispatcher, I need to run Gowanus station holds through site staff while the AMPECO API is
unreachable or its status is stale, so that Gowanus bookings stay held through a vendor outage.

## Acceptance criteria (EARS)
1. [State] While the AMPECO API is unreachable or the status held for Gowanus EVSEs is stale (older than 60 s,
   constitution N2), the Station-hold dispatcher shall send no charger reservation at Gowanus and send a site-staff
   station-hold request (SS-118) for each station hold that falls due there.
2. [Unwanted] If a site-staff request sent under clause 1 is not delivered within the site's configured site-staff
   delivery timeout, then the Station-hold dispatcher shall raise a 'station-hold request undelivered' ops exception for
   the booking (SS-219).
3. [State] While Gowanus station holds run under clause 1, the Station-hold dispatcher shall raise no
   'charger reservation failed' exception for them, as at a status-only site.
4. [Event] When the AMPECO API is reachable again and Gowanus status is fresh, the Station-hold dispatcher shall send
   the next station holds for EVSEs flagged reservable as charger reservations again.

## Notes
- "Unreachable" and "stale" come from the status service's feed state for the site (SS-203; age measured per A-031) and
  from a failed call to the AMPECO integration (SS-212). The outage itself raises one ops exception there (REQ-168);
  bookings are still accepted.
- A-012, A-048 with Q-059 (Gowanus site staff receive and acknowledge requests). Reservations accepted before the outage
  are cancelled through SS-120, with retries.
