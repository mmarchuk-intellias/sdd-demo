# SS-013 · Cancellation of active bookings with capacity returned at once

As the Booking engine, I need to cancel an active booking in a single request and return its capacity at the same
instant, so that a driver who takes a ride gives the slot back while driving and another booker can take it straight
away.

## Acceptance criteria (EARS)
1. [Event] When an authorised cancel command names a booking that is confirmed and has no recorded arrival, the
   Booking engine shall record the booking as Cancelled in that single request, with no confirmation step, with the
   sender as actor and the reason code for a cancellation by that party.
2. [Ubiquitous] The Booking engine shall stop counting a cancelled booking against any cap and in the pool check from
   the instant the cancellation is recorded, so a hold for the same slot can be placed straight away.
3. [Ubiquitous] The Booking engine shall cancel only the booking a cancel command names.
4. [Unwanted] If a cancel command names a booking that is already cancelled, released, a no-show, completed or has a
   recorded arrival, then the Booking engine shall leave the booking and any fee line unchanged and answer
   BOOKING_NOT_ACTIVE.
5. [Event] When the Booking engine records a cancellation, the Booking engine shall emit one booking-cancelled event
   that states whether the booking was allocated and which station hold it had, so that the station hold is cleared
   (SS-120), its timers stop (SS-032) and the cancellation message is sent (SS-300 clause 10).
6. [Event] When a cancellation is recorded at or after the booking's cancellation cut-off, fixed at its confirmation,
   the Booking engine shall record it in the booking's history as a late cancellation, and as before the cut-off
   otherwise.

## Notes
- Covers US-005 S1, S2, S6 (clauses 1, 2), S3 and S5 (clause 3; which booking a bare SMS keyword means is bucket-5 #5,
  SS-310), S4 (clause 4); US-112 S2 (cancelled; no fee: SS-132), S3 (clause 4), S4 (clause 6).
- "Authorised": the booker or charging driver by one tap (REQ-039, SS-327) or SMS keyword (REQ-041, REQ-242,
  SS-322), or a user of the booking's fleet in the fleet portal (SS-323). An ops release is SS-016. One-tap cancel
  needs no one-time code (REQ-241 v2, CR-001).
- Clause 6 records the cut-off only; the fee decision for a late cancellation is SS-132 under A-049 (cut-off defaults to
  the slot start, Q-042). The cut-off is a per-site parameter (SS-026).
- A repeated cancel with the same key is SS-014 (JS-421 S4).
