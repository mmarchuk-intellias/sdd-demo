# SS-424 · Encryption in transit (TLS 1.2 or later) and at rest with KMS keys

As the Platform & operations component, I need all traffic encrypted with TLS 1.2 or later, all stored data encrypted
with KMS keys in Amperlane's account, and secrets kept only in a managed secret store, so that the platform meets the
SOC 2-ready encryption agreed for day one and the safeguards the NY SHIELD Act expects.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Platform & operations component shall accept only TLS 1.2 or later (A-037) on every connection,
   external and internal, connections to the database and to the workflow engine included.
2. [Unwanted] If a client or service offers an unencrypted connection, or only a protocol older than TLS 1.2, then the
   Platform & operations component shall refuse the connection.
3. [Ubiquitous] The Platform & operations component shall encrypt at rest, with AWS KMS keys in Amperlane's account,
   every database, backup, object store, log store and the workflow engine's store.
4. [Unwanted] If a Terraform plan creates or changes a data store without encryption at rest under an Amperlane KMS
   key, then the Platform & operations component shall fail the pipeline run and apply nothing.
5. [Unwanted] If the daily configuration check finds a data store without that encryption, then the Platform &
   operations component shall alert the on-call engineer.
6. [Ubiquitous] The Platform & operations component shall keep secrets only in a managed secret store.
7. [Unwanted] If a secret is found in code, configuration, an image or repository history, then the Platform &
   operations component shall fail the pipeline run.
