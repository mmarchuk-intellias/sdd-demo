# SS-201 · Status freshness: poll reconciliation keeps connected-site status within 60 s

As the EVSE status service, I need to reconcile every connected site's EVSE status by a periodic poll as well as by
webhooks, so that a lost webhook can never leave an EVSE's status older than 60 seconds while the operator's API is
reachable.

## Acceptance criteria (EARS)
1. [Ubiquitous] The EVSE status service shall request a status poll of every connected site through the site's CSMS
   integration at the integration's configured status poll interval, whether or not webhooks are arriving.
2. [Event] When a reconciliation poll returns, for an EVSE, the same status as the one held, the EVSE status service
   shall restart that EVSE's status age and emit no status-changed event.
3. [Unwanted] If the webhook for an EVSE's status change never arrives, then the EVSE status service shall hold the
   changed status, taken from a poll, no later than 60 seconds after the CSMS reported the change.
4. [State] While a connected site's CSMS API is reachable, the EVSE status service shall keep the status age of each
   of the site's EVSEs at or below 60 seconds (constitution N1).
5. [Ubiquitous] The EVSE status service shall record, for each EVSE at a connected site and each minute of the
   availability window (constitution N4), the EVSE's highest status age in that minute and whether the site's CSMS API
   was reachable, so the monthly A-031 figure (60 seconds or less in at least 99% of the reachable minutes) can be
   computed per EVSE.
6. [Unwanted] If a connected site's CSMS API does not answer a reconciliation poll, then the EVSE status service shall
   record the minutes until it answers again as unreachable for that site, so they are not counted as breaches of the
   60-second target (A-031).

## Notes
- Covers JS-206 S2, S4 (with SS-202 for the stale display), S5 and S6, and US-203 S2.
- The poll schedule runs as a durable workflow schedule (constitution N10); the vendor calls are SS-211 and SS-214.
  Status age is measured as SS-200 clause 6 defines (A-031). The N21 dashboard and alert at 60 seconds read the
  metric of clause 5.
- R7: polling AMPECO for status is unconfirmed (Q-009, JS-206 notes); push or poll and 60-second freshness at JFK are
  unconfirmed (Q-012, integrations.md U-8). Fallback while unconfirmed: status older than 60 seconds is shown stale
  (SS-202) and a site-wide loss of status raises the feed exception (SS-203); A-031 does not count unreachable minutes.
- Parameter: the status poll interval per CSMS integration (SS-026 clause 9; default in design.md §8, A-059).
- Q-061: the vendors' allowed polling rate, and whether one request returns every EVSE of a site, decide whether the
  default interval keeps status within 60 seconds at every site (N1); how a charger that lost its connection shows in
  a poll response is part (2).
