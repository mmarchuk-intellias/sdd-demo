# SS-439 · No prototype code in the codebase: provenance check

As the Platform & operations component, I need the pipeline to keep code from the discarded Supabase prototype out of
the platform while its schema stays available as a reference, so that the platform starts clean, as the Amperlane CTO
decided.

## Acceptance criteria (EARS)
1. [Unwanted] If a change adds code that matches code of the Supabase prototype above the configured prototype
   similarity threshold, checked against a read-only snapshot of the prototype repository, then the Platform &
   operations component shall fail the pipeline run and name the matching files.
2. [Unwanted] If a build imports a file from the prototype repository, or a package published from it, then the
   Platform & operations component shall fail the pipeline run.
3. [Ubiquitous] The Platform & operations component shall keep the prototype's schema only as a read-only reference
   document outside every build.

## Notes
- Enabler: REQ-117 has no story. ADR-010 ("I'd bin it", SRC-C2@00:04:20); the prototype is Next.js 14 with Supabase
  (SRC-C2@00:03:52), and its schema was promised as a reference (SRC-C2@00:58:41).
- The similarity threshold is a new configured value (default in design.md §8, A-059).
