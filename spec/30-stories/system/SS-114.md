# SS-114 · Ops rebooking of a single booking under the same rules

As the Allocation & rebooking component, I need to let ops rebook one booking to another slot, site or EVSE in the ops
console under the rules that apply to any booking, so that rebooking needs no pilot tool and cannot break capacity or
compatibility.

## Acceptance criteria (EARS)
1. [Event] When an ops user rebooks a confirmed booking to another slot, site or, for an allocated booking, EVSE with a
   reason code from the catalogue, the Allocation & rebooking component shall check the target against the capacity,
   pool-feasibility, connector-compatibility and no-overlap rules that apply to any booking (SS-002, SS-003, SS-004,
   SS-102) and, if they hold, rebook the booking under its booking id with the ops user as actor and the reason code.
2. [Event] When an ops rebooking is done, the Allocation & rebooking component shall emit a rebooking event, so that the
   old station hold is cleared (SS-120), the station hold follows the new allocation (SS-116, SS-118) and the charging
   driver gets the rebooking notice (SS-301 clause 8).
3. [Unwanted] If the target fails any of those rules, then the Allocation & rebooking component shall refuse the
   rebooking with that rule's code and leave the booking unchanged.
4. [Unwanted] If the rebooking has no reason code from the catalogue, then the Allocation & rebooking component shall
   refuse it and leave the booking unchanged.
5. [Unwanted] If an ops user names a target EVSE for a booking that has no allocation yet, then the Allocation &
   rebooking component shall refuse the EVSE choice, since a booking gets an EVSE only at its allocation offset
   (REQ-003, SS-100).

## Notes
- REQ-058 lists rebooking among the ops-console tasks; it is the only requirement for a single manual rebooking (US-129
  S2; triage "Dropped or already covered").
- A rebooked booking is excluded from an automatic no-show fee (REQ-180, SS-131). The other ops tasks of US-129 are
  SS-015, SS-016, SS-123 and SS-222.
- Clause 2's driver message: see the GAP on rebooking messages in the Step 3.3 log (as SS-110).
