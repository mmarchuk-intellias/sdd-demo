# SS-028 · Site onboarding without code change, bookable only once live

As the Inventory & site configuration module, I need ops to onboard a site in any time zone as data, and to report it
as bookable only once ops mark it live, so that new partner sites on an integrated CSMS take bookings without a release
and never before they are ready.

## Acceptance criteria (EARS)
1. [Event] When ops enter a new site in the ops console with its station operator, address and location, a site code,
   its time zone, supply pattern, CSMS kind, EVSEs, connectors, capacity rules and partner terms, the Inventory & site
   configuration module shall store it as not live, with no code change or deployment.
2. [Ubiquitous] The Inventory & site configuration module shall accept as a site's CSMS kind only a CSMS the platform
   already integrates, or none for supply pattern C.
3. [Ubiquitous] The Inventory & site configuration module shall accept any IANA time zone for a site.
4. [Event] When ops mark live a site whose onboarding data is complete (every EVSE with a connector record, capacity
   rules that cover its bookable hours, and partner terms recorded), the Inventory & site configuration module shall
   report the site as bookable from that instant.
5. [Unwanted] If ops mark live a site whose onboarding data is incomplete, then the Inventory & site configuration
   module shall refuse it, name each missing item and keep the site not live.
6. [State] While a site is not live, the Inventory & site configuration module shall report it as not bookable to
   every caller, so the open-slot view shows no slot there (SS-001 clause 6) and holds for it are refused (SS-002
   clause 9).
7. [Unwanted] If a user who is not ops tries to create a site or mark one live, then the Inventory & site configuration
   module shall refuse it and change nothing.
8. [Unwanted] If a new site's code is already used by another site, then the Inventory & site configuration module
   shall refuse it and keep the other site's code unchanged.

## Notes
- Covers US-014 S1 – S3 and the onboarding part of S4 (the booking core part is SS-021). The open-slot view and holds
  refuse a site that is not bookable (SS-001, SS-002).
- "Without a code change" holds for a site on a CSMS the platform already integrates or with no API (US-014 S1 Given);
  a new CSMS needs a new integration (A-022, Q-007, Q-036, CF-025).
- The site code is what drivers text (REQ-061, SS-311). The site location ranks cross-site alternatives (SS-010).
- Complete-data checks reuse SS-023 (rules), SS-027 (terms), SS-030 (connectors); per-site parameters start at their
  catalogue defaults (SS-026). REQ-138's Los Angeles test site: A-013; the Los Angeles launch is parked (REQ-324).
