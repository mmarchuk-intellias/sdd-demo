# SS-313 · Station operator fault and maintenance notice by SMS within the set time

As the Messaging component, I need to send the station operator an SMS within the set time when a charger fault or a
maintenance hold changes bookings at its site, so that the operator knows which booked drivers are still coming instead
of hearing it from a driver.

## Acceptance criteria (EARS)
1. [Event] When Allocation & rebooking emits the per-booking outcomes of a charger fault (SS-108 clause 8) or of a
   maintenance hold (SS-113 clause 6) with at least one booking changed at a site, the Messaging component shall send
   one SMS notice to the registered notice contact of the site's station operator within the configured station-operator
   notice time of the fault being recorded or the hold being saved.
2. [Ubiquitous] The Messaging component shall name in the notice the site, the EVSE, the cause (charger fault, or
   maintenance with the reason code 'moved — maintenance'), the number of bookings changed and a link to the list of
   affected bookings in the station portal (SS-227).
3. [Ubiquitous] The Messaging component shall put no driver's phone number or name in the notice.
4. [Unwanted] If a charger fault or maintenance hold changes no booking, then the Messaging component shall send no
   notice for it.
5. [Unwanted] If further bookings are changed by the same fault or hold after its notice was sent, then the Messaging
   component shall send no second notice for it.
6. [Unwanted] If the station operator has no registered notice contact, or the notice is reported undelivered, then the
   Messaging component shall raise an "operator notice undelivered" ops exception (SS-219) naming the site and the
   fault or hold.

## Notes
- Settles bucket-5 item #39: an SMS through Twilio (A-008) to the operator's registered contact, with the detail in the
  station portal (SS-227, which lists each affected booking and its outcome, JS-313 S1 – S3). E-mail would need a
  provider that integrations.md does not list (an ADR if wanted).
- Clause 6 adds an exception type that ss-plan §5.1 does not list (deviation and GAP in the log).
- Bookings that still fit are not changed (JS-313 S5, data-model INV-2); fault rebooking is SS-108, maintenance-hold
  rebooking SS-113 (A-017, CF-022, A-050).
- P3.4 (2026-10-28): clause 1 is triggered by the same per-booking outcomes the station portal lists (SS-227 clause 1;
  SS-108 clause 8, SS-113 clause 6), so the notice and the list agree on which bookings changed. The parameter is named
  as in SS-026 clause 2 (station-operator notice time).
