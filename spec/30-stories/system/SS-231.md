# SS-231 · Series A data-room report for a month range, traceable to booking ids

As the reporting module, I need to produce the Series A data-room report on demand for any range of months since
October 2025, each figure traceable to the booking ids behind it, so that investors can check pilot and platform
figures down to the bookings.

## Acceptance criteria (EARS)
1. [Event] When an Amperlane user requests the data-room report for a range of months, the reporting module shall give
   each of its figures per month, computed under the configured completed definition and stating that definition.
2. [Ubiquitous] The reporting module shall give with each figure of the data-room report the list of booking ids it was
   computed from.
3. [Ubiquitous] The reporting module shall mark pilot data in the data-room report as such and give every figure with
   and without it.
4. [Unwanted] If the requested range starts before October 2025, then the reporting module shall cover only the months
   from October 2025 and state that earlier months have no data.
5. [Unwanted] If a fleet or station-operator user requests the data-room report, then the reporting module shall refuse
   the request.
6. [Event] When the report for the same range is produced again with no new evidence recorded in between, the reporting
   module shall give the same figures and the same booking ids behind each figure.

## Notes
- Covers US-328 S1 – S5.
- The figures the data room needs are not defined: Q-020, A-026 (Dana Whitfield for the data-room cut). Tests use
  completed bookings and no-shows per month (SS-230, SS-232 rules).
- Which Amperlane roles may produce the report is not stated (US-328 notes); clause 5 excludes other organisations
  only. Extracts that leave the platform are de-identified (REQ-118, SS-339); booking ids are internal ids.
- Migrated records from before 2026-02-01 carry a data-quality flag (REQ-230, SS-418); whether the report shows it is
  not stated. Depends on Q-017 and CF-018.
