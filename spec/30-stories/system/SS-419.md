# SS-419 · Sheet-versus-Airtable precedence rule with a conflict list

As the Pilot migration & cut-over component, I need every disagreement between a site's pilot Sheet and Airtable
settled by one documented, versioned precedence rule and listed, so that Priya Nair can check each decision against
what ops did on shift instead of trusting whichever source loaded last.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Pilot migration & cut-over component shall settle every disagreement between a site's pilot Sheet
   and Airtable by one documented, versioned precedence rule that names the winning source per field: the Sheet for
   slot and EVSE, Airtable for driver and fleet.
2. [Event] When a migration run finds the two sources giving different values for a field of one booking, the Pilot
   migration & cut-over component shall load the booking with the value the rule picks.
3. [Event] When a migration run finds a booking held in only one of the two sources, the Pilot migration & cut-over
   component shall load it from the source that holds it, with the fields that source lacks shown as not recorded.
4. [Unwanted] If the sources disagree on a field for which the rule names no winning source, then the Pilot migration &
   cut-over component shall choose no value, load nothing for that booking and put it on the rejected list with the
   reason "conflict not covered by the precedence rule".
5. [Unwanted] If a Sheet cell could be paired with more than one Airtable row under the documented pairing rule, then
   the Pilot migration & cut-over component shall pair none of them and put each on the rejected list with the reason
   "ambiguous pairing between Sheet and Airtable".
6. [Event] When the migration is run again under a changed rule, the Pilot migration & cut-over component shall settle
   every conflict again under the changed rule and show the changed rule's version on each conflict-list entry.
7. [Ubiquitous] The Pilot migration & cut-over component shall add no conflict-list entry for a booking whose Sheet cell
   and Airtable row agree.
8. [Ubiquitous] The Pilot migration & cut-over component shall keep the same values and produce the same conflict list
   whatever order it reads the two sources in.
9. [Event] When the rule settles a booking under clause 2 or clause 3, the Pilot migration & cut-over component shall
   add one conflict-list entry with the booking, both source values or the one source that holds it, the value kept and
   the rule's id and version.
