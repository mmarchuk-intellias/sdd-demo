# SS-018 · Fleet-priority hold of capacity for one named fleet

As the Booking engine, I need to keep a number of units of capacity at a site for one named fleet for a time window,
within the site's caps, so that a fleet whose drivers must charge at a set time finds capacity when other fleets'
bookings would fill the site.

## Acceptance criteria (EARS)
1. [Event] When an ops user places a fleet-priority hold of a number of units at a site for a time window, naming one
   fleet and a reason code, the Booking engine shall record it with the fleet, units, window, ops user, reason code and
   time, and count the units in every slot of the window against the cap and in the pool check.
2. [Ubiquitous] The Booking engine shall accept a hold for a booking of the named fleet in the window against the held
   units first, and a hold for a booking of any other fleet only from capacity outside the held units.
3. [Unwanted] If a booking of another fleet finds no capacity outside the held units, then the Booking engine shall
   refuse it with the code SLOT_FULL and the same-site offer of SS-009, and keep the held units for the named fleet.
4. [State] While the named fleet's bookings use all of the held units in a slot, the Booking engine shall accept
   further bookings of that fleet in that slot only from the capacity open to every fleet under the site's capacity
   rules.
5. [Unwanted] If a fleet-priority hold names no fleet, has no reason code, has a window that ends before it starts, or
   holds more units than the cap of a slot in its window, then the Booking engine shall refuse it with the code
   INVALID_MANUAL_HOLD and record nothing.
6. [Ubiquitous] The Booking engine shall keep the units of a fleet-priority hold that the named fleet has not booked
   for the whole of the hold's window, and apply the hold only to slots that overlap its window.
7. [Event] When an ops user shortens or ends a fleet-priority hold, the Booking engine shall return the units it no
   longer holds to every fleet at once.

## Notes
- Covers US-131 S1, S2, S4 – S6. S3 (a hold placed below confirmed bookings) is SS-019.
- Settles bucket-5 #24: unbooked held capacity stays held for the hold's whole window (REQ-335 "only"); ops can
  shorten or end the hold, which returns the capacity at once.
- Clause 1 keeps the hold inside the cap (US-131 S1, red team): it never adds capacity on top of a station's cap.
- A-018, Q-035. The audit entry for the hold is SS-332.
