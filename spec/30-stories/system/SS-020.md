# SS-020 · Actor and catalogue reason code on every booking state change

As the Booking engine, I need to record every booking state change with its actor and a specific reason code from one
fixed catalogue, so that ops can answer a driver, a fleet or a station operator from evidence, and a booking rebooked
after a fault never reads as a no-show.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Booking engine shall record every booking state change with the state before and after, its actor
   (the system or a named person), a reason code from the reason-code catalogue and the time.
2. [Ubiquitous] The Booking engine shall keep one reason-code catalogue (Notes) in which each kind of change the system
   makes on its own has its own code, and shall never record a system-initiated change with a generic code such as 'other'
   or 'system update'.
3. [Unwanted] If a state change is submitted with a reason code that is not in the catalogue, or with free text in
   place of a code, then the Booking engine shall refuse it and leave the booking's state unchanged.
4. [Ubiquitous] The Booking engine shall keep a released reason code's identifier and meaning unchanged and never reuse
   it for another reason.
5. [Ubiquitous] The Booking engine shall keep in its reason-code catalogue 'moved — session did not start' for a
   rebooking after an arrival with no charging session, distinct from 'moved — charger fault'.
6. [Event] When an ops user records a booking action with the reason code 'outage' and the time at which it actually
   happened, the Booking engine shall record both that time and the time of entry in the booking's history.
7. [Event] When the Booking engine records a booking state change, the Booking engine shall send it to the audit trail
   (SS-332) with the same actor, reason code and time.
8. [Unwanted] If any request through the platform, or any statement made with the platform's own database role, tries
   to update or delete a recorded booking state change, then the Booking engine shall refuse it and leave the recorded
   entry unchanged.
9. [Event] When a recorded booking state change is corrected, the Booking engine shall record the correction as a new
   entry that refers to the entry it corrects.
