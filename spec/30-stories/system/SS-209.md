# SS-209 · Return to service after a stable available period or an ops return

As the EVSE status service, I need to return a faulted EVSE to the pool only after it has stayed available for the
configured stable-available time or ops return it with a reason code, and never send rebooked bookings back to it, so that
drivers are not sent back to an EVSE that may fault again.

## Acceptance criteria (EARS)
1. [Event] When an EVSE excluded after a fault has reported available without interruption for the configured
   stable-available time, the EVSE status service shall return it to the pool for new allocations.
2. [Unwanted] If an EVSE excluded after a fault reports any status other than available before the stable-available
   time has passed, then the EVSE status service shall keep it out of the pool and restart the stable-available time
   from its next available report.
3. [Event] When an ops user returns an EVSE excluded after a fault to service with a reason code, the EVSE status
   service shall return it to the pool for new allocations at once and record the return with the ops user, the
   reason code and the time.
4. [Unwanted] If an ops user tries to return an EVSE to service without a reason code, then the EVSE status service
   shall refuse the return and keep the EVSE out of the pool.
5. [Event] When an EVSE returns to the pool, the EVSE status service shall emit a returned-to-service event that
   requests no change to any booking, so bookings already rebooked away from it stay on their new EVSE, site or time.
6. [Optional] Where the site's live status source is the attendant view, the EVSE status service shall count an EVSE
   the attendant set from faulted to free, and did not change since, as reporting available from the time of that
   update.

## Notes
- Covers JS-118 S1 – S5. Undoing a fault rebooking after the EVSE returns is US-122 (SS-111).
- The ops return reason code is introduced here (ss-plan §5.1); the catalogue is SS-020.
- Parameter: the configured stable-available time (REQ-194 "set time"; platform-wide in the ss-plan §5.1 list).
- GAP (batch 3 log): REQ-194 lets ops return an EVSE, but does not say whether ops may return one whose source still
  reports faulted, nor how allocation then treats it.
- S5 depends on the attendant view (U-13; A-021, Q-049, A-054). Freshness: constitution N1, N2.
