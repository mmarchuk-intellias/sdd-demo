# SS-422 · Cut-over switch: one configured instant, pilot tools out of the booking path

As the Pilot migration & cut-over component, I need one configured cut-over instant and a cut-over run that hands the
pilot sites, fleets and SMS number to the platform and leaves no pilot tool in the booking path, so that from launch
every new booking at the pilot sites for the pilot fleets is made and run in the platform.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Pilot migration & cut-over component shall hold one configured cut-over instant, which the
   carry-over (SS-421) and cut-over invoicing (SS-410) compare slot starts with, a slot starting exactly at the instant
   counting as after it.
2. [Unwanted] If, when the cut-over is due to start, a pilot site is not live in the platform, a pilot fleet has no
   registered drivers, or the configured cut-over instant is before 2027-03-01 and no approval to switch off the
   Amperlane Concierge is recorded in the go-live record (SS-423 clause 5), then the Pilot migration & cut-over
   component shall not start the cut-over and shall list what is missing for ops and the Amperlane CTO.
3. [Event] When the cut-over instant is reached with every precondition of clause 2 met (every pilot site live, every
   pilot fleet holding registered drivers and, for an instant before 2027-03-01, the switch-off approval recorded), the
   Pilot migration & cut-over component shall run the cut-over steps in order (carry over the open pilot
   bookings, SS-421; request Messaging to take over the pilot's SMS number so that the pilot bot stops answering it,
   A-057) and record each step's result and time in the cut-over record.
4. [Event] When the SMS number takeover step has run, the Pilot migration & cut-over component shall send a help
   keyword (SS-310 clause 11) to the pilot's SMS number from a test number that is registered to a fleet and has an
   agreement to booking messages in force (SS-304), and mark the step done only when the platform's Messaging component
   has answered it.
5. [Unwanted] If a cut-over step fails, the takeover test text unanswered included, then the Pilot migration & cut-over
   component shall stop, record the failed step with its error and keep the steps already done.
6. [Unwanted] If the outage copy (SS-436) holds no complete refresh (SS-436 clauses 1, 5) taken after the carry-over
   step finished and covering every pilot site, then the Pilot migration & cut-over component shall not mark the
   cut-over complete and shall show it to ops as incomplete.
7. [Unwanted] If no named Amperlane person has confirmed in the cut-over record that Airtable, the pilot Google Sheets
   and Retool no longer take new bookings, then the Pilot migration & cut-over component shall not mark the cut-over
   complete and shall show it to ops as incomplete.
8. [Ubiquitous] The Pilot migration & cut-over component shall be the only part of the platform that reads pilot data,
   only from export files, with no credential for Airtable, Google Sheets or Retool anywhere in production.
9. [Event] When the cut-over is run again after a failed step, the Pilot migration & cut-over component shall resume
   from the failed step without repeating the steps already done.
