# SS-211 · AMPECO status: webhooks and poll, status mapping, unmappable statuses

As the AMPECO integration (CSMS integrations), I need to turn Gowanus status webhooks and poll results from the AMPECO
API into normalised status events, and reject anything I cannot validate or map, so that the EVSE status service gets
only valid Gowanus status in the platform's own terms.

## Acceptance criteria (EARS)
1. [Event] When AMPECO delivers a status webhook for a Gowanus EVSE, the AMPECO integration shall pass the EVSE status
   service a normalised status event with the EVSE, the mapped platform status, AMPECO's timestamp as observed-at, the
   source "AMPECO webhook" and AMPECO's event id.
2. [Event] When the EVSE status service requests a reconciliation poll of Gowanus, the AMPECO integration shall fetch
   the status of every Gowanus EVSE through the AMPECO API and pass each as a normalised status event with the time of
   the fetch as observed-at and the source "AMPECO poll".
3. [Ubiquitous] The AMPECO integration shall map each AMPECO status value to exactly one platform status (available,
   occupied, charging, faulted or unknown), for every Gowanus EVSE whatever its reservable flag.
4. [Unwanted] If an AMPECO status payload fails schema validation, carries a status value with no mapping, or names a
   charger or EVSE id not mapped to a Gowanus EVSE, then the AMPECO integration shall reject it, pass nothing to the
   EVSE status service, and record the rejection with its reason.
5. [Unwanted] If the AMPECO API does not answer a reconciliation poll, then the AMPECO integration shall report the
   poll to the EVSE status service as failed and pass no status.
