# SS-016 · Ops force-confirm within capacity and force-release as a cancellation

As the Booking engine, I need to let ops force-confirm a hold within the site's capacity and force-release a booking
with the effect of a cancellation, each with a reason code, so that ops can settle a booking for a driver on the phone
without breaking the site's capacity rules.

## Acceptance criteria (EARS)
1. [Event] When an ops user force-confirms a hold that was never confirmed, before or after its hold time ran out,
   with a reason code from the catalogue, the Booking engine shall confirm it only if the cap re-check and the pool
   check of SS-003 pass, record the override with the ops user as actor, the reason code and the time, and emit the
   booking-confirmed event of SS-003 so the booker and the charging driver get the confirmation.
2. [Unwanted] If a force-confirm would exceed the cap of any slot it covers or fail the pool check, then the Booking
   engine shall refuse it with the reason code a confirmation would get and leave the hold as it was.
3. [Event] When an ops user force-releases an active booking with a reason code from the catalogue, the Booking engine
   shall end it with the same effect as a cancellation under SS-013 (capacity returned at once, one event that clears
   its station hold and sends the cancellation message of SS-300 clause 10), marked as an ops release with the ops
   user as actor, the reason code and the time.
4. [Unwanted] If a force-confirm or force-release arrives without a reason code, then the Booking engine shall refuse
   it with the code REASON_CODE_REQUIRED and change nothing.
5. [Ubiquitous] The Booking engine shall record a force-release with no no-show outcome, so that no no-show fee is
   created for it automatically.
6. [Event] When an ops user force-confirms or force-releases with the reason code 'outage', after a platform outage, a
   booking settled by phone during it, the Booking engine shall apply clauses 1 – 5 to it also when the booking's slot
   has already started or ended.

## Notes
- Covers US-128 S1 – S4; S5 (a retried force-release acts once) is SS-014. The confirmation message is SS-300;
  clearing the station hold is SS-120; the audit entry is SS-332.
- Settles bucket-5 #23: a force-release never creates a fee automatically; if ops judge one due, they record it with a
  reason code through the fee decision (SS-131), as REQ-180 allows.
- Clause 1 reads REQ-056's "held or unconfirmed booking" as a hold not yet confirmed, including one whose hold time
  has run out (ss-log-1); its capacity is re-checked, so the cap and the pool still hold.
- A reason code that is not in the catalogue, or free text, is refused under SS-020 (US-412 S3).
- Clause 6 is A-060 (Gate 3, 2026-10-28): what ops arranged by phone from the outage copy (SS-436) is recorded
  afterwards with the existing actions, also for a slot that has already started or ended; SS-020 clause 6 keeps the
  time of the phone call and the time of entry. Booking on behalf is SS-015 clause 4.
