# SS-125 · Session-start arrival on the allocated EVSE within the arrival window

As the Arrival & no-show component, I need to record arrival from a CSMS session start on the booking's allocated EVSE
within the arrival window, where the site's session-start evidence is confirmed, so that a driver who plugs in keeps the
booking without stopping to scan a code.

## Acceptance criteria (EARS)
1. [Optional] Where arrival from a session start is switched on for the booking's site, the Arrival & no-show component
   shall record arrival on a booking from a charging session start on its allocated EVSE inside its arrival window
   (SS-124), at the session start's time and with the CSMS session start as its source.
2. [Unwanted] If a session start is on another EVSE than the booking's allocated one, then the Arrival & no-show
   component shall record no arrival on the booking from it.
3. [Unwanted] If a session start comes before the booking's arrival window opens, then the Arrival & no-show component
   shall record no arrival on the booking from it.
4. [Unwanted] If a session start on the allocated EVSE comes after the booking was released at its end of grace, then
   the Arrival & no-show component shall keep the booking released and record neither an arrival nor a late arrival from
   it.
5. [Event] When a booking is reallocated, the Arrival & no-show component shall judge later session starts only against
   the booking's new allocated EVSE.
6. [Unwanted] If a session start is received for a booking that already has an arrival, then the Arrival & no-show
   component shall keep the first arrival and its time.
7. [State] While arrival from a session start is not switched on for a site, the Arrival & no-show component shall
   record no arrival from session starts or status changes at that site, so that QR scans (SS-124) and the attendant
   (SS-126) stay its arrival evidence.
8. [Event] When the Arrival & no-show component records arrival from a session start that does not identify the booked
   vehicle or driver, the Arrival & no-show component shall mark the arrival as an unidentified session start in the
   booking's history.

## Notes
- R7: the session-start event is unconfirmed (integrations.md U-14; Q-009, Q-012, Q-051). A-051 covers it: the evidence
  is the CSMS session-start event where Phase 0 confirms one, otherwise the EVSE's status changing to charging or
  occupied; arrival from a session start is switched on per site only once that evidence is confirmed (clauses 1 and 7);
  an unidentified start is marked (clause 8).
- Duplicated and out-of-order events are removed by SS-216 and SS-200 (constitution N9); clause 6 keeps one arrival
  whatever arrives.
- No location is involved (REQ-204, A-024). A session start after release is not a late arrival because it may be a
  walk-up's (clause 4).
