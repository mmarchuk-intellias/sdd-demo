# SS-009 · Same-site next free slot, searched to the end of the day's bookable hours

As the Booking engine, I need to find the earliest free compatible slot at the same site, up to the end of that day's
bookable hours, and hold it for the booker when a requested slot is full, so that a booker who lost a slot can take
the next one with one more confirmation instead of searching again.

## Acceptance criteria (EARS)
1. [Event] When a hold or a confirmation is refused because a slot is full (SS-002, SS-003), or a text booking names a
   time that is not on the site's time grid (SS-311 clause 4), the Booking engine shall search the site's time grid
   from the requested start time (clause 4) to the end of that day's bookable hours, in the site's time zone, for the
   earliest start time at which a hold for the same vehicle and duration would be accepted, and return it as an offer.
2. [Event] When the Booking engine returns an offer under clause 1, the Booking engine shall place a hold on the offered
   slot for the booker that expires at the site's configured hold time and counts and expires like any other hold
   (SS-002).
3. [Event] When another component asks for a same-site offer for an existing booking, after a no-show release with a
   late arrival, after a fault or maintenance hold left the booking unplaced, or because the site is full at
   station-hold time or at the pre-arrival check, the Booking engine shall return the earliest start time from the
   later of the booking's slot start and the time of the request to the end of that day's bookable hours at which a
   hold for the booking's vehicle and duration would be accepted, without holding it.
4. [Event] When an offer is asked for from a time that is not on the site's time grid, the Booking engine shall start
   the search at the first start time on the grid after that time.
5. [Unwanted] If no start time from the start of the search to the end of that day's bookable hours would accept a
   hold, then the Booking engine shall answer that the slot is full and nothing is free at the site that day, and hold
   nothing.

## Notes
- Covers JS-004 S1, S2 (the offered hold expires as any hold), S4; US-214 S2 and S6 (the search behind the text reply,
  SS-311; P3.4 2026-10-28: clause 1 now also starts on an off-grid texted time, which SS-311 clause 4 answers with a
  held offer while SS-002 clause 2 alone would refuse it with no offer); JS-106 S1 (the offer behind REQ-038, made by
  SS-128); JS-019 S1, S3 and JS-120 S1 (the same-site part of the alternatives, requested by SS-105 and SS-109).
  Compatibility of offers is SS-004 (JS-004 S3, JS-106 S5, JS-120 S5); the order among losers is SS-007 (JS-004 S5).
- Settles bucket-5 #4: the search runs from the requested time to the end of the site's bookable hours that day in
  the site's time zone; if nothing is free the answer says so (A-034's explicit "full") and nothing is held.
- Only REQ-008's offer is held (clause 2). REQ-038, REQ-049 and REQ-148 do not hold their offers; acceptance re-checks
  the slot and answers a taken slot with a new offer (SS-011). The start of those searches (the later of slot start
  and request time) is this batch's reading, logged in ss-log-1.
- Parameters: hold time, time grid, bookable hours (SS-026, SS-023). Message timing (REQ-038, REQ-049 set times) and
  text belong to the requesting components and Messaging (SS-316).
