# SS-001 · Open-slot view shows only holdable slots, overnight included

As the Booking engine, I need to answer an open-slot query for a site, a vehicle and a duration with exactly the start
times at which a hold would be accepted, so that bookers see only slots the site will take and spend no taps on slots
it would refuse.

## Acceptance criteria (EARS)
1. [Event] When an open-slot query names a site, a vehicle the requester may book and one of the site's configured
   booking durations, the Booking engine shall return as open exactly those start times on the site's time grid, within
   the site's bookable hours, at which a hold for that vehicle and duration would be accepted at the moment of the
   query (SS-002, SS-004).
2. [Ubiquitous] The Booking engine shall return a start time as open only if every slot that a booking of the chosen
   duration from that start time would cover is below the cap of the capacity rule for that slot, counting unexpired
   holds and confirmed bookings.
3. [Ubiquitous] The Booking engine shall return no start time as open at a site where no EVSE is compatible with the
   chosen vehicle under SS-004.
4. [Ubiquitous] The Booking engine shall offer and accept start times between 01:00 and 05:00 Eastern time, and
   bookings that run across 01:00, under the site's bookable hours and capacity rules exactly as at any other time,
   with no exclusion for the planned maintenance window.
5. [Unwanted] If an open-slot query covers start times outside the site's bookable hours, then the Booking engine shall
   return none of those start times as open.
6. [Unwanted] If the query names a site that the Inventory & site configuration module reports as not bookable
   (SS-028), then the Booking engine shall return no open start time for that site.
7. [Unwanted] If no start time is open for the query on the requested day, then the Booking engine shall return an
   explicit "no slot free" result, not an error, so the requester can change the site, the vehicle or the duration.
8. [Unwanted] If a hold request names a start time outside the site's bookable hours, then the Booking engine shall
   refuse the hold with the code OUTSIDE_BOOKABLE_HOURS and place no hold.

## Notes
- P3.4 (2026-10-28): old clause 5 joined the query and the hold refusal; the hold refusal is now clause 8.
- Covers US-001 S1 – S4 (clauses 1 – 3), US-033 S1 – S4 (clauses 4, 5 and 8), US-212 S2 and S6 (clauses 1 and 7).
  US-212 S3 and S4 refusals are SS-002; "sees the slots free at that moment" is a new query under clause 1.
- Clause 4 is REQ-152, which holds under A-028, the working assumption for CF-015 (needs-decision, Q-024): the
  constitution R6 flag carried by US-033 applies to this clause. "Eastern time" follows REQ-152; at a site in another
  time zone its bookable hours alone decide (SS-021).
- A start time shown as open can still fail the pool check at confirmation (SS-003, A-014, CF-023) or be taken first
  by another booker (US-001 note).
- Relies on: SS-002 (hold rules), SS-004 (compatibility), SS-021 (times in the site's zone), SS-022 (presets),
  SS-023 (capacity rules and bookable hours), SS-028 (live sites). Parameters: time grid, booking durations (SS-026).
