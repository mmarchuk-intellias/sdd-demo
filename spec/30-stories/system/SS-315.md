# SS-315 · Status messages to booker-only numbers so small fleets follow bookings without the portal

As the Messaging component, I need to send a booking's booker-only number a short status message as the booking's
evidence comes in, so that a small-fleet owner knows whether each booked cab arrived and is charging without signing in
to the fleet portal or opening links.

## Acceptance criteria (EARS)
1. [Event] When arrival is recorded for a booking whose booker is a booker-only number, the Messaging component shall
   send that number a status message with the booking code, the vehicle's plate, the site and the arrival time.
2. [Event] When a charging session start is recorded for such a booking, from the CSMS or the attendant, the Messaging
   component shall send the booker-only number a status message that charging started, with its time.
3. [Event] When such a booking is released at the end of grace with no arrival, the Messaging component shall send the
   booker-only number a status message that it was released with no arrival, with the time of release.
4. [Event] When SS-107 reports that no charging session started after arrival for such a booking, the Messaging
   component shall send the booker-only number a status message that the vehicle arrived and is not charging.
5. [Event] When the outcome of a charge that did not start is decided for such a booking, a rebook at the site or a
   fault case with ops, the Messaging component shall send the booker-only number a status message with that outcome.
6. [Event] When such a booking is rebooked, the Messaging component shall send the booker-only number a status message
   naming the new site, start time or EVSE and the rebook's reason code.
7. [Ubiquitous] The Messaging component shall state in each status message the evidence time the platform recorded,
   the same time the fleet's view (SS-225) and ops' booking view show.
8. [Unwanted] If the same evidence event reaches the Messaging component more than once, then the Messaging component
   shall send its status message once.
