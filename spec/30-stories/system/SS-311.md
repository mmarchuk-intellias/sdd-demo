# SS-311 · Text booking: site code and time to a booking or an offer, with no ops action

As the Messaging component, I need to turn a text such as "GOW 1645" from a registered number into a confirmed booking
or an offer of the next free slot, with no ops action, so that drivers keep booking by text as they do today but get
an answer at once.

## Acceptance criteria (EARS)
1. [Event] When an inbound message from a registered driver number reads as a site code followed by a time, the
   Messaging component shall ask the booking engine for a hold and its confirmation at that site and time, with the
   presets of SS-022 and the provider message id as idempotency key, with no ops action.
2. [Ubiquitous] The Messaging component shall read the time in a text booking as its next occurrence in the site's time
   zone.
3. [Event] When the booking engine confirms a text booking, the Messaging component shall reply with that booking's
   confirmation (SS-300), naming the site, date, start time, vehicle and duration, and send the sender no second
   confirmation.
4. [Unwanted] If the requested slot has no room for the preset vehicle and duration, or the time is not on the site's
   time grid, then the Messaging component shall create no booking for that time and reply with the next free
   compatible slot that the booking engine offers and holds (SS-009), with its hold time and the accept keyword.
5. [Unwanted] If no compatible slot is free until the end of the site's bookable hours that day, then the Messaging
   component shall reply that the site is full for that day and hold nothing.
6. [Unwanted] If an accept keyword for an offered slot arrives after the offer's hold expired, then the Messaging
   component shall handle the accept as a new text booking for that slot (clauses 1, 3 and 4), not as a confirmation of
   the expired hold.
7. [Unwanted] If the site code matches no site, then the Messaging component shall create no hold or booking and hand
   the message to SS-312 as not understood.
8. [Unwanted] If no vehicle can be preset for the sender, then the Messaging component shall book nothing and reply
   asking the driver to pick a vehicle through the driver page link.
9. [Unwanted] If the sender is a booker-only number, then the Messaging component shall book nothing and reply with a
   driver page link, where the charging driver is named (SS-005).
10. [Ubiquitous] The Messaging component shall ask for no SoC, location or other vehicle data in any text-booking
    reply.
11. [Event] When the Pilot migration & cut-over component requests the takeover of the pilot's SMS number (SS-422
    clause 3, A-057), the Messaging component shall handle every SMS sent to that number from then on as an inbound
    message to the platform, text bookings and keywords included.

## Notes

  offer acceptance in time is SS-011 through the accept keyword (SS-310, US-214 S3).
- Unregistered or removed numbers book nothing: SS-318, SS-319, SS-312. Burst fairness: SS-007.
- Clause 9 is a GAP in the log: a booker-only number must name the charging driver (REQ-201), which the text format
  cannot carry.
- Text bookings use Twilio (A-008); WhatsApp works the same way where enabled (SS-308). REQ-061 is Y; its final KYIV
  is set at Step 5 (US-213 notes).
