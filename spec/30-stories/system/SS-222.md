# SS-222 · Shift without pilot tools: every pilot booking task available in the console

As the ops console, I need to offer every booking task ops perform on a pilot shift, from taking a request to answering
a driver, with no path to the pilot tools, so that from the launch date nobody opens Airtable, Google Sheets or Retool
to run a booking.

## Acceptance criteria (EARS)
1. [Ubiquitous] The ops console shall offer every booking task of an ops shift in the pilot: taking a booking request
   and booking on a registered driver's behalf, confirming, arranging a station hold, rebooking, releasing and
   answering a driver, each carried out by the core component that owns it.
2. ~~[Event] When an ops user completes one of these tasks in the ops console, the ops console shall show its result on
   the booking with the ops user as actor, the reason code and the time.~~ Superseded by clause 7 (v2, Gate 4; Notes).
3. [Unwanted] If a booking's 'contact the site' exception (SS-119) is open when an ops user records in the ops console
   that its station hold was arranged with the site, then the ops console shall pass that record, with the ops user and
   the time, to the Station-hold dispatcher (SS-123 clause 4).
4. [Event] When an ops user opens a site in manual mode, the ops console shall show the site's timed list of station
   holds to arrange (SS-123).
5. [Event] When an ops user answers, from the ops console, a driver message the platform could not act on, the ops
   console shall send the answer through messaging on the driver's channel (SS-314) and record it against the driver's
   booking.
6. [Ubiquitous] The ops console shall neither read booking data from nor write booking data to Airtable, Google Sheets
   or Retool.
7. [Event] When an ops user completes one of these tasks in the ops console, the ops console shall show its result on
   the booking with the ops user as actor and the time, and, for every task that changes the booking's state or
   overrides a booking rule (booking on a driver's behalf, confirming, arranging a station hold, rebooking and
   releasing), the reason code it was recorded with; an answer to a driver is shown with the ops user, the time, the message
   and the reason code OPS_ANSWERED_DRIVER (SS-020).
