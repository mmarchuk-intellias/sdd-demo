# SS-213 · AMPECO session records: read once available, deduplicated, late records accepted

As the AMPECO integration (CSMS integrations), I need to read every Gowanus session record from the AMPECO API once
Kinship makes them available, each exactly once and however late, so that settlement can match each Gowanus booking
to the station operator's own record of the charge.

## Acceptance criteria (EARS)
1. [Optional] Where Kinship makes session records available through the AMPECO API, the AMPECO integration shall read
   new Gowanus session records at the configured session-record read interval and deliver each to settlement with its
   EVSE, start, end and energy as AMPECO reports them, its AMPECO record id and the time it was received.
2. [Unwanted] If the AMPECO API does not answer when session records are read, then the AMPECO integration shall resume
   from the last record it delivered once the API answers, so that no record of the outage period is missed.
3. [Unwanted] If AMPECO returns a session record the AMPECO integration has already delivered (the same AMPECO record
   id), then the AMPECO integration shall deliver nothing new for it.
4. [Ubiquitous] The AMPECO integration shall deliver a session record whenever AMPECO makes it available, however long
   after the session ended, keeping the session's own start and end separate from the time it was received.
5. [Unwanted] If a session record fails schema validation or names an EVSE not mapped to a Gowanus EVSE, then the
   AMPECO integration shall deliver nothing for it and record the rejection with its reason.
6. [Optional] Where the AMPECO API offers no session records for Gowanus, the AMPECO integration shall deliver no
   session record for Gowanus.
7. [Ubiquitous] The AMPECO integration shall read Gowanus status (SS-211) and handle charger reservations (SS-212) in
   the same way whether or not session records are available.

## Notes
- Covers US-202 S1 – S5. Storing, retrieving by EVSE and time window, and matching are settlement (SS-407); a booking
  without a session record goes to the reconciliation queue (SS-408, REQ-214).
- R7: per-session records from AMPECO are unconfirmed (integrations.md U-6, Q-009); clause 6 is the fallback. Which
  fields AMPECO gives beyond EVSE, start, end and energy is part of Q-009. A-022 sets the baseline.
- Parameter: the configured session-record read interval (new; default in design.md §8, A-059).
- P3.4 (2026-10-28): old clause 6 split into clauses 6 and 7 (US-202 S4, third Then).
