# SS-310 · Keyword replies in English, Spanish and Bengali

As the Messaging component, I need to understand short keyword replies in English, Spanish and Bengali and apply each
one to the booking it names, so that a driver who cannot open the booking page can still cancel, report running late,
take or decline an offered slot, report a faulted EVSE or get help with one word.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Messaging component shall recognise each keyword of its catalogue (cancel, running late, accept,
   decline, fault, help, link, STOP, START) in English, Spanish and Bengali, Bengali in script and in common Latin
   transliteration, Spanish with or without accents, in any letter case and with surrounding spaces ignored.
2. [Event] When a recognised keyword arrives, the Messaging component shall act on it whichever of the three languages
   it is written in and reply in the sender's stored language (SS-303).
3. [Event] When a cancel, running-late, accept, decline or fault keyword carries a booking code, the Messaging
   component shall apply it to that booking only, once SS-322 has authorised the sender.
4. [Event] When a cancel, running-late, accept, decline or fault keyword carries no booking code and the sender has
   exactly one active booking to which it applies, the Messaging component shall apply it to that booking, once SS-322
   has authorised the sender.
5. [Unwanted] If such a keyword carries no booking code and the sender has more than one active booking to which it
   applies, then the Messaging component shall change no booking and reply listing those bookings' codes and how to
   resend the keyword with one.
6. [Unwanted] If the booking a keyword names does not exist, is no longer active, or has no open offer for an accept or
   decline, then the Messaging component shall change no booking and reply saying why.
7. [Event] When a cancel keyword is applied, the Messaging component shall ask the booking engine to cancel the booking
   (SS-013) and reply naming the booking cancelled by its code, site and start time.
8. [Event] When a running-late keyword is applied, the Messaging component shall pass the report to SS-129 and reply
   that it was recorded.
9. [Event] When an accept keyword, with an option number where several slots were offered, or a decline keyword is
   applied, the Messaging component shall pass it to the booking engine (SS-011) and reply with the booked slot, the
   next free slot offered instead, or the decline.
10. [Event] When a fault keyword is applied, the Messaging component shall pass a driver fault report for the booking
    to SS-210 and reply that ops were told.
11. [Event] When a help keyword arrives from a registered number, the Messaging component shall reply in the sender's
    language with the keywords and how to reach ops, change nothing, and not list the message for ops as not
    understood.
12. [Event] When a link keyword arrives from a registered number, the Messaging component shall reply to that number
    with a new driver link issued by SS-320.
13. [Event] When a STOP or START keyword arrives, the Messaging component shall pass it to SS-304 for the channel it
    arrived on.
14. [Unwanted] If an inbound message matches no keyword and is not a text booking (SS-311), then the Messaging
    component shall hand it to SS-312 as not understood.

## Notes
- Settles bucket-5 item #5: every message about a booking names it by a short booking code (SS-302); a keyword with the
  code acts on that booking; a bare keyword acts on the driver's only active booking; with several, the reply lists
  their codes and changes nothing (REQ-041 "that booking only"). Gate 3 (2026-10-28, G3-1 option (a)): US-005 v2 S3
  and S5 have the reply carry the code of the SMS it answers, which each message asks for (clause 3); bucket-5 #5 stays
  as clauses 4, 5 and 7, with its residual risk (a bare keyword meant for an older message cancels the only active
  booking, and clause 7's reply names it).
- Settles bucket-5 item #27: keywords per language are set with Amperlane's bilingual ops team (A-042); "link" sends a
  new link (REQ-240); "help" meets the carrier's HELP rule once Q-047 is answered; START is recorded as agreement
  (SS-304), subject to Q-056.
- Deviation from the catalogue: JS-117 and REQ-191 added. REQ-191 lets a driver report a faulted EVSE "by message"
  (JS-117 S2), and REQ-220's list has no fault keyword; the alert itself is SS-210.
- The cancellation, the running-late report and offer acceptance are SS-013, SS-129 and SS-011; idempotency of inbound
  messages is SS-309; sender authorisation is SS-322 (JS-228 S6).
- P3.4 (2026-10-28): parent JS-217 added: JS-217 S5 (a keyword is acted on and not listed for ops as not understood) is
  met by clauses 2 – 10 and 14. Clause 7's reply is also the charging driver's cancellation message when the charging
  driver sent the keyword (SS-300 clause 11). KYIV stays K.
- P3.4 final pass (2026-10-28, handoff H12 from critic Z): clause 11 answered a help keyword from any number, while
  SS-312 clauses 5 and 6 send an unregistered number no reply unless replies to unregistered numbers are enabled
  (Q-056). Clause 11 now covers registered numbers only, as clause 12 does; a help keyword from an unregistered number
  follows SS-312 clauses 5 and 6. If the carrier's HELP rule (Q-047) requires an answer to every sender, SS-312 clause
  5 is where to exempt it.
