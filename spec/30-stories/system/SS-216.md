# SS-216 · Session-start events from the CSMS where provided, normalised and deduplicated

As the CSMS integrations, I need to deliver each charging session start a site's CSMS reports, once, in the platform's
own terms and with whatever identifier it carries, so that arrival, charge-not-started and today's charging view can
use it as evidence at sites where it is confirmed.

## Acceptance criteria (EARS)
1. [Optional] Where a site's CSMS integration declares the session-start capability (SS-217), the site's CSMS
   integration shall deliver each session start the CSMS sends as a normalised session-start event with the site, the
   EVSE, the CSMS's start time, the provider event id and any vehicle, token or account identifier the CSMS sends.
2. [Optional] Where a site's CSMS integration does not declare the session-start capability, the site's CSMS integration
   shall deliver no session-start event for that site.
3. [Unwanted] If the CSMS sends a session start the integration has already delivered (the same provider event id, or
   the same EVSE and start time), then the CSMS integration shall not deliver it again.
4. [Unwanted] If a session-start event carries no identifier of the vehicle, token or account, then the CSMS
   integration shall deliver it marked as unidentified.
5. [Unwanted] If a session-start event fails schema validation or names an EVSE not mapped to the site, then the CSMS
   integration shall deliver nothing for it and record the rejection with its reason.
6. [Ubiquitous] The CSMS integrations shall deliver every valid session start whether or not the EVSE has a booking,
   leaving the matching to a booking and its arrival window to Arrival & no-show (SS-125).

## Notes
- Covers the CSMS side of JS-103 S1 – S7 (S6 through clause 3; S7 through clause 2: arrival then comes from the QR
  scan, SS-124), JS-111 S1 – S4 and JS-309 S1 and S4. Arrival from a session start is SS-125; charge not started is
  SS-107; today's view is SS-225.
- A-051: where no session-start event is confirmed, a session start is evidenced by the EVSE's status changing to
  charging or occupied (SS-200 status-changed events; the attendant's "occupied" at LIC, SS-207). Consumers apply that
  rule; this SS adds no event of its own for it.
- R7: session-start events are unconfirmed at every site (integrations.md U-14): Q-009, Q-012, Q-051. Clause 4 is
  A-051 (4), so a dispute can tell an unidentified session start from a scan.
- P3.4 (2026-10-28): clauses 1 and 2 were conditioned on "Phase 0 has confirmed", a project status no test can observe;
  they now use the declared capability of SS-217 clause 3, which is set once Phase 0 confirms the feed (A-051).
