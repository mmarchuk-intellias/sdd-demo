# SS-322 · Sender authorisation: booking-changing messages only from the booker or charging driver

As the Identity & access component, I need to accept a command about a booking sent by SMS or WhatsApp only from the
registered number of that booking's booker or charging driver, so that nobody else can cancel or change a booking by
text.

## Acceptance criteria (EARS)
1. [Event] When a command about a booking (cancel, running late, accept, decline or fault) arrives by SMS or WhatsApp,
   the Identity & access component shall authorise it only if the sender's number is that booking's booker or charging
   driver and is still registered to the booking's fleet.
2. [Unwanted] If the sender is any other number, another driver of the same fleet, a number registered to no fleet and
   a number removed from the booking's fleet included, then the Identity & access component shall refuse the command,
   so the booking stays unchanged.
3. [Unwanted] If a command is refused, then the Identity & access component shall have no message sent to the booker or
   the charging driver saying that the booking changed.
4. [Ubiquitous] The Identity & access component shall apply the same rule to SMS and WhatsApp.
5. [Event] When a command is refused, the Identity & access component shall record a security event with the sender's
   number, the booking and the time (SS-334).

## Notes
- Depends on A-006 and A-023. A booker removed from the fleet after making the booking can no longer change it
  (US-222 S6): A-052, working assumption for Q-045.
- Which booking a keyword applies to is SS-310 (#5); new bookings by a removed number are refused by SS-319 (US-219 S1,
  S3). Constitution SC3 applies to every message command.
