# SS-340 · Location kept only as derived arrival events; raw readings deleted

As the Audit & data protection component, I need location to be kept only as the arrival events derived from it, with
every raw reading deleted, so that the platform holds no trace of a driver's whereabouts.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Audit & data protection component shall keep location only as derived arrival events, each holding
   the booking, the kind of evidence and the time, encrypted at rest and readable only by the roles the data register
   names for it.
2. [Event] When an arrival event is derived from a raw location reading, the Audit & data protection component shall
   delete that raw reading.
3. [Unwanted] If a raw location reading yields no arrival event, then the Audit & data protection component shall
   delete it no later than the end of its booking's grace period.
4. [Unwanted] If a raw location reading is still stored after the end of its booking's grace period, then the Audit &
   data protection component shall delete it and raise an alert.
5. [Ubiquitous] The Audit & data protection component shall keep raw location out of logs, traces and error responses
   (constitution SC5).

## Notes
- Enabler: REQ-256 has no story. It applies once a location feature is admitted: REQ-173 and REQ-175 are I, so in the
  committed plan no raw reading arrives (A-024; the consent guard is SS-341).
- Depends on A-025 and Q-022. Ops read location evidence only within an open dispute (REQ-259, SS-135); views are
  logged (SS-335).
