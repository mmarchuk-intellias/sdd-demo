# SS-008 · Booking API latency and the five-times burst load test

As the Booking engine, I need to answer booking operations within the agreed latency during the shift-change burst
and pass the five-times load test without overlaps or duplicates, so that drivers get an answer at once when
contention peaks.

## Acceptance criteria (EARS)
1. [Ubiquitous] The Booking engine shall answer the booking operations listed in A-032 in under 300 ms at the 95th
   percentile, measured server-side from the platform edge per 10-minute window, including the wait in the per-site
   order and the database constraint check.
2. [Event] When the load test of A-034 sends 2,000 booking attempts in 10 minutes to staging, with A-034's contention
   profile and idempotency-key retries, the Booking engine shall answer them in under 300 ms at the 95th percentile.
3. [Event] When that load test has run, the Booking engine shall hold zero overlapping active allocations on any EVSE,
   allocations made during the test included.
4. [Event] When that load test has run, the Booking engine shall have created zero duplicate bookings from the
   retries that reuse an idempotency key.
5. [Event] When that load test has run, the Booking engine shall have answered at least 99.9% of the attempts without
   a server error (A-034).
6. [Event] When that load test has run, the Booking engine shall have answered every attempt that lost a contended
   slot with a same-site offer or an explicit SLOT_FULL answer.
7. [Unwanted] If a run of that load test misses any of clauses 2 – 6, then the Booking engine shall be recorded as
   failing the release gate of constitution D6 for the release under test.

## Notes
- Covers JS-010 S2 (clause 1) and S6 (clauses 2 – 6). Clause 7 (P3.4, 2026-10-28) is the [Unwanted] clause the
  playbook asks for where failure is possible; it restates the release gate of constitution D6 and N6.
- Depends on A-032 (operations and where latency is measured), A-034 (profile, seeded volume, pass criteria), A-009,
  CF-026 (400 is the modelled launch burst). Constitution N3 and N6; the run is a release gate (D6).
- Zero overlaps rest on the database exclusion constraint (SS-103) and the allocation rule (SS-102); zero duplicates on
  SS-014; the answers to losers on SS-007. The production latency metric per hour is the N21 dashboard.
