# SS-208 · Fault intake: faulted EVSE out of new allocations and one fault event within the set time

As the EVSE status service, I need to take an EVSE whose status turns faulted out of new allocations and emit one fault
event within the configured fault reaction time, from whichever source reported it, so that fault rebooking starts
before a driver arrives at the EVSE instead of after a driver's text.

## Acceptance criteria (EARS)
1. [Event] When the current status of an EVSE changes to faulted, whether from a CSMS webhook, a CSMS poll or the
   attendant, the EVSE status service shall exclude the EVSE from new allocations within the configured fault reaction
   time of receiving that status.
2. [Event] When the current status of an EVSE changes to faulted, the EVSE status service shall emit exactly one fault
   event with the site, the EVSE, the observed-at time and the source within the configured fault reaction time of
   receiving that status, which starts fault rebooking (SS-108).
3. [Event] When the EVSE status service emits a fault event, the EVSE status service shall raise one ops exception of
   type "fault" naming the site, the EVSE and the observed-at time.
4. [Unwanted] If a faulted status arrives for an EVSE whose current status is already faulted, then the EVSE status
   service shall emit no further fault event and raise no further fault exception.
5. [Unwanted] If a faulted status arrives with an observed-at time earlier than that of the EVSE's current status, then
   the EVSE status service shall keep the EVSE in the pool and emit no fault event.
6. [Ubiquitous] The EVSE status service shall carry out fault intake with no ops action, recording the system as the
   actor of the exclusion and of the fault event.

## Notes
- Covers JS-116 S1 – S6 (S6: the EVSE is excluded; with no bookings SS-108 sends no message), US-205 S4 (the same
  intake at all three patterns) and the intake part of JS-330 S3.
- Fault path (ss-plan §5.1): this SS detects and emits one fault event; SS-108 decides per booking; SS-036 ends the
  saga in a defined state; SS-109 – SS-111 handle the rest. The end-to-end bound "starts fault rebooking within the
  set time" (REQ-047) is checked on the simulator with the Gowanus replay (SS-115, constitution D6).
- Deviation from ss-plan §5.1: REQ-189 lists "fault" as an exception type, but no SS was named to raise it; this SS
  raises it (EVSE-level, so closing it leaves no ops action in any booking's trail, JS-330 S3).
- Parameter: the configured fault reaction time (REQ-047 "set time"; platform-wide in the ss-plan §5.1 list).
- Webhook and poll: Q-009, Q-012; duplicates and order: SS-200, constitution N9. LIC faults depend on the attendant
  view (U-13; A-021, Q-049, A-054).
