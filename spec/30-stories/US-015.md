# US-015 · Change per-site booking parameters without a deployment

As a member of Amperlane ops, I want to change a site's booking parameters (time grid, durations, buffer, hold time, allocation and
pre-arrival offsets, reminder lead time, grace and its maximum extension) without a deployment, so that each site runs
on the terms of its partner agreement as soon as they are signed.

## Acceptance criteria

Scenario: S1 (happy path) A change applies to bookings confirmed after it
  Given a site has a configured value for each parameter of REQ-146: time grid, durations, buffer, hold time, allocation offset, pre-arrival offset, reminder lead time, grace and maximum grace extension
  When ops changes any one of them in the ops console
  Then bookings at that site confirmed after the change use the new value
  And no deployment took place
  And the audit trail records who changed which parameter and when

Scenario: S2 (failure) A change is not applied to bookings confirmed before it
  Given a booking at a site was confirmed before ops shortened the site's allocation offset
  When that booking's allocation time comes
  Then it is allocated at the offset in force when it was confirmed

Scenario: S3 (failure) Only ops can change per-site parameters
  Given a station operator or a fleet manager is signed in
  When that user tries to change a site's booking parameters
  Then the change is refused
  And the parameters stay unchanged

Scenario: S4 (edge) A hold placed before the change and confirmed after it uses the new values
  Given a booker placed a hold at a site
  And ops then changed the site's grace period
  When the booker confirms the hold
  Then the booking uses the new grace period

Scenario: S5 (edge) A new time grid does not shift existing bookings
  Given confirmed bookings at a site start on the site's current time grid
  When ops changes the site's time grid
  Then those bookings keep their start times and durations
  And new bookings use the new grid

## Notes

- Depends on: A-001 (grid, durations, buffer, hold time), A-002 (allocation and pre-arrival offsets), A-003 (grace),
  A-011 (reminder lead time), A-020 (maximum grace extension; the extension itself is an ops override, CF-021
  needs-decision). Gate 2 set REQ-146 to Y.
- S1 covers every parameter of REQ-146, not only grace (Step 3.1 red-team pass): with grace alone, the other values
  could stay constants in code and the story would still pass.
- Capacity rules are not in this list; the station operator changes them (REQ-077, EP-09).
- Before-and-after values in the audit trail are REQ-262 (EP-13).
