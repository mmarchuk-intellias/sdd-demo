When I have arrived for my booking but no charging session starts on my EVSE, I want to be rebooked at the site or
have ops take it up as a fault, with no no-show fee, so I can still charge and am not charged for an EVSE that did not
work.

## Acceptance criteria

Scenario: S1 · happy path · Rebooked to another EVSE at the site
  Given arrival is recorded on a booking allocated to EVSE A
  And no charging session starts on EVSE A within the set time after arrival
  And another compatible EVSE at the site is free
  When the set time passes
  Then no no-show fee line is created for the booking
  And the booking is rebooked to the free compatible EVSE at the site
  And the charging driver gets a message naming the new EVSE

Scenario: S2 · failure · No compatible EVSE is free
  Given arrival is recorded on a booking allocated to EVSE A
  And no charging session starts on EVSE A within the set time after arrival
  And no compatible EVSE at the site is free
  When the set time passes
  Then no no-show fee line is created for the booking
  And the booking appears in the ops exception queue as a fault case for EVSE A

Scenario: S3 · failure · Grace ends while the driver waits
  Given arrival is recorded on a booking and no charging session has started
  When the booking's grace period ends
  Then the booking is not released
  And no no-show fee line is created for it

Scenario: S4 · edge case · A session that starts within the set time
  Given arrival is recorded on a booking allocated to EVSE A
  When a charging session starts on EVSE A within the set time after arrival
  Then the booking is neither rebooked nor sent to ops

## Notes

- How a session start is evidenced: a CSMS session-start event or status where available (U-14; Q-009, Q-012, Q-051),
  or the attendant at LIC (A-021, U-13, Q-049). A-051 sets the evidence per site: the session-start event where Phase 0
  confirms one, otherwise the EVSE's status changing to charging or occupied (the attendant's "occupied" at LIC); the
  same evidence decides whether a charging session started for REQ-181.
- The reason code for a rebook after a failed session start (REQ-053 needs one from the catalogue) is a design detail
  for Step 3.3.
- S1 applies the allocation message of REQ-200 (FT-06.4). Fault rebooking of the EVSE itself is EP-04 (JS-116, JS-123).
