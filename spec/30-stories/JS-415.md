# JS-415 · Know who has seen a driver's personal data

When a driver says someone misused their phone number, or Amperlane needs to know who has seen a driver's personal
data, I want every view and export of that driver's personal data by an ops, finance, fleet, station-operator or
site-staff user on record, so I can tell the driver, counsel or an auditor exactly who saw what and when.

## Acceptance criteria

Scenario: S1 (happy path) A fleet manager opens a driver's details
  Given a Borough Green fleet manager
  When the fleet manager opens the details of one of the fleet's drivers
  Then the view is recorded with the user, the organisation, the driver, the data shown and the time

Scenario: S2 (happy path) Ops exports a list with phone numbers
  Given an ops person
  When the ops person exports a list of bookings that includes drivers' phone numbers
  Then the export is recorded for every driver in it, with the user, the data exported and the time

Scenario: S3 (failure) Data read through the API instead of a portal page
  Given a fleet user reads a driver's personal data through the platform's API
  When the response is returned
  Then the read is recorded in the same way as a view in the portal

Scenario: S4 (failure) Someone tries to remove the record
  Given a recorded view of a driver's personal data
  When any user tries to edit or delete that record
  Then the attempt is refused
  And the record is unchanged

Scenario: S5 (edge case) Location evidence viewed in a dispute
  Given an open dispute on a no-show
  When an ops person views the driver's location evidence for that booking
  Then the view is recorded with the ops person, the driver, the booking and the time

Scenario: S6 (edge case) The driver is later anonymised
  Given recorded views of a driver's personal data
  When the driver is anonymised on request (US-418)
  Then the records of who viewed what remain, referring to the driver's pseudonym

Scenario: S7 (happy path) A list that shows drivers' personal data
  Given a Borough Green fleet manager
  When the fleet manager opens the list of the fleet's bookings, which shows each booking's driver name
  Then the view is recorded for every driver shown in the list, with the user, the data shown and the time

Scenario: S8 (edge case) Finance and site-staff views are recorded too
  Given a finance user and a site-staff user of LIC Garage Depot
  When the finance user opens a dispute that shows a driver's personal data
  And the site-staff user opens a view of the bookings due at LIC that shows a driver's personal data
  Then each view is recorded with the user, the driver, the data shown and the time

## Notes

- SHIELD Act safeguards and SOC 2 evidence (CTX-108, CTX-110). Ops may see location evidence only within an open
  dispute (REQ-259, EP-03).
- REQ-263 v2 (CR-006) names ops, finance, fleet, station-operator and site-staff users (S8). Which driver data site
  staff see is Q-048, covered by A-053 (the plate and the charging driver's first name only); S8 holds whatever they
  are shown.
- These records are what JS-416 uses to scope a breach through a compromised account.
- Red team: recording only the driver detail page passes S1 while every list, search result and dashboard that shows
  names goes unrecorded; S7 closes it.
