# JS-421 · A repeated tap gives one booking and one answer

When I tap confirm, cancel, "running late" or accept an alternative on bad 4G and nothing seems to happen, I want to
tap again without risk, so I can get exactly one booking and one answer, never two bookings or two confirmations.

## Acceptance criteria

Scenario: S1 (happy path) A second tap on confirm
  Given a driver taps confirm on a hold and the response does not reach the phone
  When the driver taps confirm again on the same screen
  Then the second request carries the same idempotency key as the first
  And exactly one booking exists
  And the second response shows the same booking as the first
  And the driver receives one confirmation message

Scenario: S2 (failure) The same key with a different request
  Given a confirmed booking made with an idempotency key
  When a request for a different slot arrives with the same idempotency key
  Then the request is rejected as a reused key
  And no booking or hold changes

Scenario: S3 (failure) The repeat arrives after the hold's time to confirm has passed
  Given a driver's confirm made a booking, but the response did not reach the phone
  And the hold's time to confirm has since passed
  When the repeated confirm with the same idempotency key arrives
  Then the response shows the booking the first confirm made, not an expired hold
  And exactly one booking exists

Scenario: S4 (edge case) A second tap on cancel
  Given a driver taps cancel on a booking and the response does not reach the phone
  When the driver taps cancel again on the same page
  Then the booking is cancelled once
  And the second response is the result of the first cancel, not an error
  And the driver receives one cancellation message

Scenario: S5 (edge case) A second tap on "running late"
  Given a driver taps "running late" on a booking's page and the response does not reach the phone
  When the driver taps "running late" again on the same page
  Then the booking carries one running-late report
  And the driver receives one answer

Scenario: S6 (edge case) Accepting an alternative twice
  Given a driver is offered an alternative slot, taps accept, and the response does not reach the phone
  When the driver taps accept again on the same offer
  Then the driver has exactly one booking from that offer
  And the driver receives one confirmation for it

Scenario: S7 (edge case) Delivery reports arrive twice or out of order
  Given a confirmation message that reached the driver's phone
  When the messaging provider reports it as delivered before reporting it as sent, or reports it as delivered twice
  Then the message's delivery status ends as delivered
  And the confirmation is not sent to the driver again
