# US-411 · Portal users see only their own organisation's data

As the Amperlane CTO, I want every portal user to see only their own organisation's data (a fleet user only that
fleet's vehicles, drivers, bookings and invoices; a station operator only its own sites and no driver phone numbers;
an attendant only the current day's bookings at their site), so that fleets and station operators can share one
platform without seeing each other's drivers, bookings or invoices, and drivers' phone numbers never reach a station
operator.

## Acceptance criteria

Scenario: S1 (happy path) A fleet manager sees only their fleet
  Given a Borough Green fleet manager signed in to the fleet portal
  When the fleet manager opens the list of bookings
  Then only bookings for Borough Green vehicles are shown
  And only Borough Green's vehicles, drivers and invoices are reachable, in the portal and through the API it uses

Scenario: S2 (failure) A fleet manager opens another fleet's booking by its link
  Given a Borough Green fleet manager holds the link to a Five Boroughs booking
  When the fleet manager opens it
  Then access is refused
  And the response does not show whether that booking exists

Scenario: S3 (failure) A station operator looks for driver phone numbers or another operator's site
  Given a Kinship Charging user signed in to the station portal
  When the user views upcoming bookings at Gowanus and then asks for bookings at JFK
  Then the Gowanus bookings are shown without any driver phone number, on the page, in its exports and in the API
    responses behind it
  And the request for JFK is refused

Scenario: S4 (failure) An attendant asks for tomorrow's bookings
  Given the LIC attendant signed in to the attendant view
  When the attendant asks for tomorrow's bookings at LIC or today's bookings at Gowanus
  Then neither is shown
  And only today's bookings at LIC remain visible

Scenario: S5 (edge case) A driver who drives for two fleets
  Given a driver registered to both Borough Green and Five Boroughs
  When each fleet's manager looks at that driver
  Then each sees the driver, but only the bookings made for their own fleet's vehicles
  And nothing shown to either manager reveals that the driver also drives for the other fleet

Scenario: S6 (edge case) The attendant's day changes at midnight
  Given the LIC attendant is signed in shortly before midnight in the site's time zone
  When midnight passes
  Then the attendant view shows the new day's bookings at LIC and no longer the previous day's

## Notes

- Which driver data station operators and attendants may see to verify an arrival is Q-048, covered by A-053 (the
  vehicle's plate and the charging driver's first name only); these AC only fix that phone numbers are not shown to
  station operators, which holds under any answer. Driver in several fleets: A-016. "Current day"
  uses the site's time zone (A-013).
- Amperlane ops and staff access are not portal access; they are US-410 (REQ-120). Every refusal is also a security
  event (JS-413). Constitution SC3 (a user of another fleet, site or role is refused) applies to every endpoint.
- R7: whether the LIC attendant will use the attendant view is unconfirmed (U-13; Q-010, Q-005). S4 and S6 apply
  where an attendant uses it.
- Red team: hiding data in the page while the API or an export still returns it passes a UI-only test; S1 and S3 name
  the API and exports. With overnight bookings allowed (A-028), a booking at 00:15 needs its station hold before
  midnight, when it is still "tomorrow's" booking for the attendant (S6); what "the current day" covers around
  midnight is a design detail for Step 3.3.
