# US-211 · Every booking message opens the booking in the phone's browser

As a driver, I want every message about my booking to carry a link that opens that booking in my phone's browser,
with nothing to install, so that I can see and act on the booking between rides without an app-store download or an
account.

## Acceptance criteria

Scenario: S1 (happy path) The confirmation link opens the booking
  Given a driver with a confirmed booking has received the confirmation message
  When the driver taps the link in it
  Then the driver page for that booking opens in the phone's browser
  And no step asks the driver to install anything from an app store, sign up or enter a password

Scenario: S2 (happy path) Every kind of booking message carries the link
  Given every message template the platform uses for a message about a booking, among them the confirmation,
    reminder, allocation notice, re-offer, fault notice, site-full notice and cancellation reply
  When a message from each template is sent for one booking
  Then every one of them carries a link that opens the driver page for that same booking

Scenario: S3 (failure) The link has stopped working
  Given the set time after the booking's grace period has passed (REQ-240)
  When the driver taps a link from a message about that booking
  Then the booking is not shown
  And the page tells the driver how to get a new link by texting from the registered number

Scenario: S4 (failure) The booking has ended or been cancelled
  Given the driver cancelled a booking earlier
  When the driver taps the link in that booking's confirmation before the link stops working
  Then the driver page shows the booking as cancelled
  And it offers no action that would change the cancelled booking

Scenario: S5 (edge case) A message on WhatsApp
  Given the driver receives the confirmation on WhatsApp
  When the driver taps the link in it
  Then the same driver page for that booking opens in the phone's browser

Scenario: S6 (edge case) A weak connection on a small phone
  Given a phone with a 360 px wide screen on a throttled 4G connection
  When drivers open the driver page from a message link
  Then the page is usable within 3 s at p75 and the booking can be acted on without horizontal scrolling
    (constitution N24)

## Notes

- The PWA is the agreed channel (CF-001, ADR-009); native iOS and Android apps are REQ-321 (V). Driver links without a password
  follow A-006.
- S3 depends on REQ-240 (US-220) for how long a link works; the set time is configured.
- S5 depends on WhatsApp, which is unconfirmed (integrations.md U-10, Q-034, A-008).
- S6 numbers come from constitution N24 (A-043).
