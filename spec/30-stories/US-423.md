# US-423 · Amperlane owns the code, the AWS accounts and the data

As the Amperlane CTO, I want all platform code in Amperlane's repositories, all infrastructure and data in Amperlane's
AWS accounts under Amperlane's Terraform, and my engineers able to export all platform data in open formats without
Intellias' help, so that Amperlane owns its product outright instead of renting it from its vendor, and can change or
leave the vendor at any time.

## Acceptance criteria

Scenario: S1 (happy path) The CTO reviews where everything lives
  Given the platform in production
  When the Amperlane CTO reviews its repositories and cloud resources
  Then every repository holding platform code belongs to Amperlane
  And every cloud resource of every environment is in an Amperlane AWS account and defined in Terraform kept in Amperlane's repositories

Scenario: S2 (happy path) Amperlane engineers export all platform data
  Given an Amperlane engineer with the export role
  When the engineer exports all platform data
  Then the export completes without any action by Intellias
  And every file is in an open format that can be read without proprietary tools
  And the export is written to storage in Amperlane's production AWS account

Scenario: S3 (failure) A resource created outside Terraform
  Given a cloud resource created by hand in an Amperlane AWS account
  When the next drift check runs
  Then it reports the resource to Amperlane as not defined in Terraform

Scenario: S4 (failure) Intellias loses access
  Given all Intellias access to Amperlane's repositories and AWS accounts is removed
  When Amperlane's engineers build, test, deploy and export the platform
  Then each of these works with Amperlane's accounts and repositories alone

Scenario: S5 (edge case) The export is complete, not only current bookings
  Given the platform holds migrated pilot history, the audit trail and the ledger
  When an Amperlane engineer exports all platform data
  Then the export includes the migrated pilot history, the audit trail and the ledger as well as current bookings

## Notes

- "The IP has to be ours… the startup rents its own product. Not doing that" (SRC-C2@00:06:05); Intellias' default is
  "code in your repos, your AWS accounts, your Terraform" (SRC-C2@00:06:41). Constitution code conventions row 2 (no
  hand-made resources, daily drift check) applies.
- The stack, the modular monolith and the self-hosted workflow engine (REQ-134 – REQ-136) are enablers. Working in the
  same repositories from Phase 0 is US-424.
- Red team: a full export holds driver names and phone numbers. Taken outside production it falls under REQ-118
  (JS-405), so S2 keeps it in the production account; access to it follows REQ-120 (US-410). S4 is the real test of
  ownership: a pipeline, Terraform state or image registry left in an Intellias account fails it.
