As Amperlane ops, I want to make a booking on behalf of a registered driver under the same rules as the driver's own
booking, so that a driver who phones in, or a small fleet that does not use the portal, still gets a slot.

## Acceptance criteria

Scenario: S1 · happy path · Ops book for a registered driver
  Given a driver registered to a fleet and a vehicle of that fleet
  When an ops user books a slot at a site for that driver and vehicle
  Then the booking is confirmed with ops recorded as booker and the driver as charging driver
  And the charging driver gets the booking confirmation in the driver's language

Scenario: S2 · failure · The slot is full under the site's capacity rules
  Given the chosen slot has no capacity left under the site's capacity rules
  When an ops user tries to book it for the driver
  Then the booking is refused
  And the ops user is offered the next free compatible slot at the site

Scenario: S3 · failure · The vehicle is not compatible
  Given no EVSE at the site has a connector the vehicle can use natively or with an allowed adapter
  When an ops user tries to book a slot at that site for the vehicle
  Then the booking is refused

Scenario: S4 · failure · The number is not registered to the fleet
  Given a mobile number that is not registered to the fleet, or was removed from it
  When an ops user tries to book for that number on the fleet's behalf
  Then the booking is refused

Scenario: S5 · failure · The hold expires before ops confirm
  Given an ops user picked a slot for a driver, which placed a hold
  When the hold time passes without confirmation
  Then no booking is made
  And the capacity returns to the slot calendar

Scenario: S6 · edge case · A retried request makes one booking
  Given an ops user's booking request is sent twice with the same idempotency key
  When both requests arrive
  Then one booking exists

## Notes

- Small fleets barely use a portal (CTX-030); ops register their drivers (A-023, REQ-206).
- "The same rules" are REQ-004, REQ-008, REQ-013, REQ-145 and REQ-202; booker and charging driver follow REQ-009,
  whose v2 (CR-002) records the ops user who made the booking as booker, so S1 agrees with it; the confirmation
  follows REQ-088; S6 follows REQ-236. How an ops booker sees the confirmation (in the ops console, not by SMS) is a
  design detail for Step 3.3.
