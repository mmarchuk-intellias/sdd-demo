When I start charging at my allocated EVSE at a site whose CSMS reports session starts, I want to have my arrival
recorded from that session start, so I can keep my booking without stopping to scan a code.

## Acceptance criteria

Scenario: S1 · happy path · A session start on the allocated EVSE records arrival
  Given a booking is allocated to EVSE A at a site whose CSMS sends session-start events
  And the time is after the set time before the slot start and before the end of the booking's grace period
  When the CSMS reports a session start on EVSE A
  Then arrival is recorded on the booking from the CSMS session start, with the time of the event

Scenario: S2 · failure · A session start on another EVSE does not count
  Given a booking is allocated to EVSE A and is inside its arrival window
  When the CSMS reports a session start on EVSE B of the same site
  Then no arrival is recorded on the booking from that event

Scenario: S3 · failure · The previous driver's session does not count
  Given a booking is allocated to EVSE A and its arrival window has not opened
  When the CSMS reports a session start on EVSE A
  Then no arrival is recorded on the booking

Scenario: S4 · failure · A session start after grace does not count
  Given a booking allocated to EVSE A was released at the end of its grace period with no arrival
  When the CSMS reports a session start on EVSE A
  Then the booking stays released
  And no arrival within grace is recorded on it

Scenario: S5 · edge case · After a reallocation only the new EVSE counts
  Given a booking was reallocated from EVSE A to EVSE B before its slot
  When the CSMS reports a session start on EVSE B inside the arrival window
  Then arrival is recorded on the booking
  And a session start on EVSE A no longer records arrival for it

Scenario: S6 · edge case · A repeated session-start event records one arrival
  Given arrival was recorded on a booking from a CSMS session start
  When the CSMS sends the same session-start event again
  Then the booking keeps one arrival, with the time of the first event

Scenario: S7 · edge case · A site whose CSMS sends no session start
  Given a booking at a site whose CSMS does not send session-start events
  When the driver scans the QR code at an EVSE of the site inside the arrival window
  Then arrival is recorded on the booking from the QR scan

## Notes

- R7: the session-start event is unconfirmed (integrations.md U-14). AMPECO is confirmed only to send status-change
  webhooks, ChargeLab's events are unknown and LIC has none: Q-009, Q-012. A-051 covers the gap: a session start is
  evidenced by the CSMS's session-start event where Phase 0 confirms one, otherwise by the EVSE's status changing to
  charging or occupied, and arrival from a session start is switched on for a site only once that evidence is
  confirmed for it (S1, S7).
- S1 – S7 can all pass while a walk-up's session on the allocated EVSE inside the arrival window is recorded as the
  booked driver's arrival. Whether the CSMS event can tell the booked vehicle or driver from a walk-up is Q-051; until
  it is answered, A-051 records a session start that does not identify them as unidentified in the booking's history,
  so a dispute can tell it from a scan. The AC hold under any answer to Q-051.
- Duplicated and out-of-order events: constitution N9, REQ-106 (FT-14.3).
- Arrival by QR scan is US-101; drivers who share no location, US-104.
