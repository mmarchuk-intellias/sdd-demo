When a faulted EVSE starts reporting available again, I want to have it back in the pool only after it has stayed
available for a set time or after ops return it, with drivers already rebooked left where they are, so I can avoid
sending drivers back to an EVSE that may fault again.

## Acceptance criteria

Scenario: S1 · happy path · Available for the set time
  Given EVSE A was faulted and taken out of allocation
  And some of its bookings were rebooked to other EVSEs
  When the CSMS reports EVSE A as available without interruption for the set time
  Then EVSE A is back in the pool for new allocations
  And the bookings already rebooked stay on their new EVSE, site or time

Scenario: S2 · happy path · Ops return the EVSE earlier
  Given EVSE A was faulted and has reported available for less than the set time
  When an ops user returns EVSE A to service with a reason code
  Then EVSE A is back in the pool for new allocations at once
  And the return is recorded with the ops user, the reason code and the time

Scenario: S3 · failure · The EVSE faults again before the set time
  Given EVSE A was faulted and then reported available
  When it reports a fault again before the set time has passed
  Then EVSE A stays out of the pool
  And the set time starts again from its next available report

Scenario: S4 · failure · A return without a reason code is refused
  Given EVSE A is out of the pool after a fault
  When an ops user tries to return it to service without a reason code
  Then the return is refused
  And EVSE A stays out of the pool

Scenario: S5 · edge case · The LIC attendant sets the EVSE free
  Given EVSE C at LIC was set to faulted by the attendant
  When the attendant sets EVSE C to free and changes nothing for the set time
  Then EVSE C is back in the pool for new allocations

## Notes

- A flapping EVSE would expose drivers again (CTX-047). Undoing a fault rebooking after the EVSE returns is US-122.
- S5 depends on the attendant view (U-13; A-021, Q-049). Status freshness follows constitution N1 and N2.
