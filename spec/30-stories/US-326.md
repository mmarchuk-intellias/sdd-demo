# US-326 · Completed-booking definition set by ops over stored evidence

As Amperlane ops, I want to set which bookings count as completed from the evidence the platform stores for every
booking, without a deployment, so that the north-star figure follows whatever definition the founders choose (Q-017)
without waiting for a release, and every booking keeps the evidence any of their candidate definitions needs.

## Acceptance criteria

Scenario: S1 (happy path) The evidence is stored for every booking
  Given bookings that arrived and charged, were rebooked, or were released
  When Amperlane ops opens any one of them
  Then it shows its arrival, its session-record match with energy, its rebooks and the reason codes of its state changes

Scenario: S2 (happy path) Ops changes the definition without a deployment
  Given completed bookings are counted by the default definition, the Completed state
  When Amperlane ops changes the definition to "a session record is matched with energy above zero"
  Then the next completed-booking report counts under the new definition and states it, with no deployment
  And the change is recorded with who made it and when

Scenario: S3 (failure) A definition over evidence the platform does not store
  When Amperlane ops sets a definition that uses anything other than the booking's state, arrival, session-record
    match, energy, rebooks and reason codes
  Then the definition is refused and the current one stays in force

Scenario: S4 (failure) Fleet and station operator users cannot change it
  When a fleet manager or a station operator tries to change the definition
  Then the request is refused

Scenario: S5 (edge case) Evidence that arrives later
  Given a booking with a recorded arrival whose session record has not arrived yet
  And a definition that requires a matched session record
  When the completed bookings are counted
  Then the booking is not counted
  And it is counted once its session record arrives and is matched

Scenario: S6 (edge case) A late driver who was rebooked
  Given a booking released as a no-show and the rebooked booking that followed it and charged
  When the definition counts rebooked bookings
  Then the rebooked booking counts as completed and the original no-show booking does not
  And when the definition excludes rebooked bookings, neither counts

## Notes

- Q-017 is an undecided client decision (A-027 withdrawn); nothing here assumes its answer. The default definition is
  the Completed state (glossary, "Completed booking").
- Configuration changes are audit-logged (REQ-121, EP-13). Invoicing per completed booking is parked (REQ-271).
- Whether figures already reported for past months are recounted or kept is Q-054 (a client decision, with Q-017); no
  scenario here decides it. Red team: the "so that" used to promise recounting past months, and S3 used to refuse the
  default definition (the Completed state) because the state was not among the allowed fields; both fixed.
