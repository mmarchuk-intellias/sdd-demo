As Amperlane ops, I want to do every booking task of my shift in the ops console, from taking a request to answering a
driver, so that nobody opens Airtable, Google Sheets or Retool to run a booking.

## Acceptance criteria

Scenario: S1 · happy path · A whole shift in the ops console
  Given an ops user is signed in to the ops console after the launch date
  When during one shift the ops user takes a booking request from a driver, confirms a booking, arranges a station hold, rebooks a booking, releases a booking and answers a driver
  Then each task is completed in the ops console
  And each result shows on its booking with the ops user, the reason code and the time

Scenario: S2 · happy path · Rebook a single booking
  Given a confirmed booking
  When an ops user rebooks it to another slot, EVSE or site, with a reason code
  Then the booking is rebooked under the same capacity and compatibility rules as any booking
  And the charging driver gets a message about the new booking

Scenario: S3 · failure · Site staff did not acknowledge a station hold
  Given site staff have not acknowledged a station-hold request by the pre-arrival check
  And the exception is in the ops console
  When the ops user records in the console that the station hold was arranged with the site
  Then the booking shows the station hold as arranged by ops, with the time
  And the exception leaves the queue

Scenario: S4 · failure · A driver message the platform cannot understand
  Given a driver sent a message the platform cannot understand
  And it reached the ops console with the driver's language shown
  When an ops user answers it from the ops console
  Then the answer reaches the driver on the driver's channel
  And it is recorded against the driver's booking

Scenario: S5 · failure · A site in manual mode
  Given ops switched a site to manual mode
  When an ops user opens the site in the ops console
  Then the console gives a timed list of the station holds to arrange
  And the slot calendar still accepts bookings for the site

Scenario: S6 · edge case · Nothing goes to the pilot tools
  Given the launch date has passed
  When bookings are made, confirmed, rebooked or released in the platform
  Then no booking data is read from or written to Airtable, Google Sheets or Retool

## Notes

- Launch success: "Nobody opens Airtable" (CTX-139). This story is the acceptance check of REQ-058; each task is
  delivered by its own story: taking a request (US-127), confirming and releasing (US-128), the queue (US-124),
  fault rebooking (JS-119 – JS-123), answering a driver (US-126). Station-hold exceptions are REQ-026 and REQ-156,
  unparsed messages REQ-222, manual mode REQ-170.
- Apart from REQ-058, no requirement states that ops can rebook a single booking to another slot, EVSE or site;
  REQ-058 (K) lists rebooking as an ops-console task, S2 covers it here, and Step 3.3 derives the system story from it.
- A-046 and Q-041: how JFK staff acknowledge station holds.
