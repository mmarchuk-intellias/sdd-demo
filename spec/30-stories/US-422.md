# US-422 · A simulated site to break chargers on purpose, and a staging that never touches production

As an Amperlane engineer (Priya Nair), I want a simulated site where I can make chargers fault, sessions overrun and
drivers arrive late on demand, with staging connected only to sandboxes and simulators, so that I can rehearse a day
like the Gowanus charger fault before it happens to real drivers, without ever touching a real charger, a real payment
or a real driver.

## Acceptance criteria

Scenario: S1 (happy path) A charger fault on the simulated site
  Given a simulated site in staging with confirmed bookings on one of its EVSEs
  When an engineer makes that EVSE's simulated charger fault
  Then the fault reaches the platform in staging as a status change through the same integration a real site of that
    supply pattern uses, not by a write into the platform's own data
  And the platform in staging detects the charger fault and rebooks the affected bookings as it would at a real site
  And the Gowanus fault replay ("1:50 PM, charger fault, nine bookings") runs as a repeatable test

Scenario: S2 (happy path) An overrun and a late driver on demand
  Given a simulated site in staging with a booking allocated to an EVSE
  When an engineer makes the previous session overrun into the booking's slot, or reports the simulated driver as late
  Then the platform in staging handles the overrun or the late arrival as it would at a real site

Scenario: S3 (failure) Staging configured against a production system
  Given a staging integration configured with a production endpoint or live credentials (the AMPECO production API, live payments, a messaging sender that reaches real phone numbers)
  When staging starts that integration
  Then the integration is not started
  And no request reaches the production system

Scenario: S4 (failure) A simulator command aimed at a real site
  Given an engineer in staging
  When the engineer sends a simulator command that names an EVSE of a real site
  Then the command is refused
  And nothing is sent to that EVSE

Scenario: S5 (edge case) No AMPECO sandbox yet
  Given Kinship has not yet provided AMPECO sandbox access
  When staging runs
  Then the AMPECO integration in staging runs against the simulator

Scenario: S6 (edge case) Staging seeded with pilot history
  Given staging is seeded with the migrated pilot history
  When staging sends a booking message
  Then it reaches no real driver's phone
