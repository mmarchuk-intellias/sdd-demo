# JS-210 · A site's status feed goes down or an EVSE goes silent

When a site's status feed goes down or one of its EVSEs stops reporting, I want bookings to go on within the capacity
rules, any EVSE that falls silent while the rest of its site keeps reporting to be kept out of allocation, and to be
told before the next allocation, so I can step in before a driver arrives at an EVSE nobody can vouch for.

## Acceptance criteria

Scenario: S1 (happy path) Bookings continue while the feed is down
  Given JFK's status feed is unavailable
  When a driver asks for a slot at JFK that fits the site's capacity rules
  Then the booking is accepted
  And JFK's EVSE status is shown as stale with its age in every view

Scenario: S2 (failure) Ops is told before the next allocation
  Given JFK's status feed became unavailable before the allocation offset of the next JFK booking
  When that booking's allocation runs
  Then an ops exception for JFK's unavailable feed was already in the ops queue before that allocation ran

Scenario: S3 (failure) One EVSE stops reporting
  Given Gowanus's feed is working and its other EVSEs keep reporting
  When one Gowanus EVSE sends no status for the site's set silence time
  Then its status is shown as unknown
  And no new booking is allocated to it
  And ops gets an alert naming the site and the EVSE

Scenario: S4 (failure) A booking that does not fit is refused as usual
  Given JFK's status feed is unavailable
  When a driver asks for a slot at JFK that would exceed the site's capacity rule
  Then the booking is refused as it would be with the feed working

Scenario: S5 (edge case) The silent EVSE reports again
  Given a Gowanus EVSE is unknown because it stopped reporting
  When it sends a status again
  Then its status is no longer unknown
  And it can be allocated again, unless the status it sends is a fault

Scenario: S6 (edge case) The whole feed is down longer than the silence time
  Given JFK's status feed has been unavailable for longer than the set silence time, so no JFK EVSE reports
  When ops looks at JFK
  Then bookings within the capacity rules are still accepted
  And no JFK EVSE is marked unknown or kept out of new allocations by the silence rule
  And each JFK EVSE shows its last status flagged as stale, with its age
  And the ops exception for JFK's unavailable feed is in the queue

Scenario: S7 (edge case) LIC has no API
  Given the LIC attendant has not updated an EVSE's status for hours
  When ops looks at LIC
  Then the EVSE is not marked unknown by the silence rule
  And it shows "last updated by attendant at <time>"

## Notes

- "I" is Amperlane ops. "The site's set silence time" is a configured value (requirements.md: "a set time").
- S6: REQ-169 v2 (CR-004) applies the silence rule only to an EVSE that goes silent while other EVSEs at its site still
  report, so a site-wide feed outage falls under REQ-168 alone and allocation goes on. How allocation uses each EVSE's
  last known status during the outage, and station holds through site staff at Gowanus (REQ-167), are design details
  for Step 3.3.
- S7: LIC status depends on the attendant view (A-021, Q-049; integrations.md U-13).
- S5 applies the plain reading ("unknown" ends when status arrives); when a silent EVSE returns to the pool is a design
  detail for Step 3.3. A faulted EVSE returns per REQ-194.
- Depends on Q-012 (JFK feed) and Q-023 (who acts on the alert at night). A-031: an outage is not a freshness breach.
