# JS-217 · A message the platform cannot understand reaches ops

When I text Amperlane something the platform cannot act on by itself, I want it to reach an ops person who can see
which language I speak, and to be told in my language that it arrived, so I can get an answer without phoning.

## Acceptance criteria

Scenario: S1 (happy path) An unclear message from a Bengali-speaking driver
  Given a registered driver whose language is Bengali
  When the driver texts a message the platform cannot understand
  Then the message is listed for ops in the ops console with its full text, the driver and the language Bengali shown
  And the driver gets an acknowledgement in Bengali

Scenario: S2 (failure) The driver has no language set
  Given a registered driver with no language set
  When the driver texts a message the platform cannot understand
  Then the message is listed for ops showing that no language is set
  And the driver gets an acknowledgement in English

Scenario: S3 (failure) The message is written in another language
  Given a registered driver whose language is Spanish
  When the driver texts an unclear message written in English
  Then ops sees the driver's language as Spanish
  And the acknowledgement is in Spanish

Scenario: S4 (failure) The unclear message is delivered twice
  Given an unclear message was listed for ops and acknowledged
  When the messaging provider delivers the same message id again
  Then ops has one item for it and the driver gets one acknowledgement

Scenario: S5 (edge case) A message the platform understands
  Given a registered driver with a booking
  When the driver replies with a keyword the platform understands, such as cancel
  Then the platform acts on it
  And it is not listed for ops as not understood

## Notes

- Language rules are REQ-199 (US-227); keywords are REQ-220 (JS-228); deduplication is REQ-090 (JS-216).
- The acknowledgement must not promise a response time: ops hours are undecided (Q-023).
- What happens to a message from a number that is not registered (no driver, no language) is a design detail for
  Step 3.3.
- Where ops reads these messages is the ops console (FT-07.1); the full message history view is REQ-196 (I).
